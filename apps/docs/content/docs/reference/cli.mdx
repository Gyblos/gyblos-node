The `gyblos` command runs and manages a seller node. This page lists every command, its options and its
exit codes.

## How to run gyblos [#how-to-run]

| Install                                 | Run a command as                                                        |
| --------------------------------------- | ----------------------------------------------------------------------- |
| Docker seller, container running        | `docker compose exec seller gyblos COMMAND`, from `~/gyblos-seller`     |
| Docker seller, container stopped        | `docker compose run --rm seller gyblos COMMAND`, from `~/gyblos-seller` |
| Native seller (macOS, Linux or Windows) | `gyblos COMMAND`                                                        |
| Source checkout                         | `pnpm gyblos COMMAND`, from the repository                              |

Replace `COMMAND` with a command from the table below. The examples on this page use the Docker form.

## Commands [#command-index]

| Command                                     | Options                                                | Exit codes                                                |
| ------------------------------------------- | ------------------------------------------------------ | --------------------------------------------------------- |
| `gyblos start`                              | None                                                   | Runs until stopped                                        |
| `gyblos setup`                              | `--role seller --mint MINT`                            | 0 keys ready; non-zero on failure                         |
| `gyblos tokenizer`                          | None                                                   | 0 verified; non-zero on failure                           |
| `gyblos --version`                          | None                                                   | 0                                                         |
| `gyblos --help` / `gyblos -h`               | None                                                   | 0 prints usage to stdout                                  |
| `gyblos config validate`                    | `--config PATH`                                        | 0 valid; 1 invalid or usage error                         |
| `gyblos doctor`                             | `--online`                                             | 0 no failed check, even with warnings; 1 a failure        |
| `gyblos seller status`                      | `--online`                                             | 0 only for `RUNNING`; 1 for any other state or error      |
| `gyblos seller register`                    | None                                                   | 0 registered or already registered; 1 failure             |
| `gyblos seller rpc`, `rpc set`, `rpc reset` | None                                                   | 0 shown or saved; 1 failure, nothing changed              |
| `gyblos seller verify github USER`          | `--gist URL`; or `--status`, `--cancel` without `USER` | 0 verified, shown or cancelled; 1 not verified or failure |
| `gyblos seller init`                        | See [`seller init`](#init-flags-for-a-native-checkout) | 0 written; 1 failure; 130 prompt cancelled                |
| `gyblos seller service install`             | `--memory SIZE`, `--cpu PERCENT`, `--dry-run`          | 0 success; 1 failure                                      |
| `gyblos seller service uninstall`           | `--dry-run`                                            | 0 success; 1 failure                                      |
| `gyblos seller service restart`             | `--dry-run`                                            | 0 success; 1 failure or not installed                     |
| `gyblos logs`                               | See [`logs`](#local-operational-logs)                  | 0 read completed; 1 usage error or unreadable data        |

There is no `gyblos stop`, and no general `--home`, `--relay`, `--rpc-url` or `--discovery-url` flag.
Stop a Docker seller with Compose and a native seller through its service (see
[Operate and update](/en/sellers/operate)). Use the
[environment variables](/en/reference/configuration#environment-overrides) for other overrides.

### start [#start]

`gyblos start` runs the seller node in the foreground with `GYBLOS_CONFIG`, or `./config.toml`. The
Docker image and the background service run it for you. Don't start a second seller on the same home.

### setup and tokenizer [#setup-and-tokenizer]

`gyblos setup --role seller --mint MINT` creates the seller's owner, node and payment keys and prints its
public role. It keeps keys that already exist, and adds payment keys to a seller that lacks them. It
contacts no RPC and funds nothing. `gyblos tokenizer` downloads and verifies the pinned public tokenizer
and prints `Pinned tokenizer verified.` The installer runs both for you.

### --version [#version]

`gyblos --version` prints the release version. A source checkout prints `source`.

## Check the configuration [#validate-the-mounted-configuration]

```sh
cd ~/gyblos-seller
docker compose run --rm seller gyblos config validate --config /config/config.toml
```

On success it prints `OK`, the effective settings and where each came from, the offers, and the names of
secret variables with `set` or `not set`. On failure it prints issue codes and key paths. It never prints a
value from the environment, and it shows URLs as origins only. Still review the output before you share
it. `config validate` parses the file and the environment; it doesn't check the engine or other startup
conditions. `gyblos doctor` does.

Each command picks its configuration file differently:

| Command                                | Configuration file                                                  |
| -------------------------------------- | ------------------------------------------------------------------- |
| `config validate`                      | `--config PATH`, otherwise `./config.toml`; ignores `GYBLOS_CONFIG` |
| `start`, `doctor`, `seller init`       | `GYBLOS_CONFIG`, otherwise `./config.toml`                          |
| `seller status`, `register`, `service` | Don't accept `--config`                                             |

In the Docker container, pass `/config/config.toml` to `config validate` explicitly.

## Diagnose startup [#diagnose-startup]

```sh
cd ~/gyblos-seller
docker compose run --rm seller gyblos doctor
```

Doctor prints `OK`, `WARN` or `FAIL` for each check, with codes and hints, then the effective seller limits
and the seller's public identity. It doesn't start a seller, generate an answer or write state. It probes
local engines only. `--online` also asks remote engines for their model lists and checks the clock against
the discovery index; it sends provider credentials to the configured provider. A passing doctor doesn't
prove that the model can generate. See [Troubleshooting](/en/help/troubleshooting) for failures.

## Status and registration [#status-and-registration]

```sh
cd ~/gyblos-seller
docker compose exec seller gyblos seller status
docker compose exec seller gyblos seller status --online
docker compose exec seller gyblos seller register
docker compose exec seller gyblos seller verify github USER
```

`seller status` is read-only. `--online` also looks up the seller's NodeId in the discovery index. While
the index refuses or fails this seller's publication, the discovery line adds `publishing refused:` and a
static code. While a model is served, an `uptime` line shows how often the index accepted this seller's
presence over the last 24 hours, 7 days and 30 days, and either `online, last presence … ago` or
`offline since …`, and a `github` line shows the GitHub account the index links to this seller and its
state; those lookups send the public NodeId to the index. The
activity summary comes from signed receipts kept on the machine; it is not a quota balance. The
`receipt queue` line shows receipts waiting to upload to the metrics collector, the bytes reserved for
them and any rejected writes. `FULL` means new receipts can't be saved until some are uploaded. On a
release build, status also reports when a newer release exists (see
[Data and privacy](/en/reference/data-and-privacy#update-checks)).

`seller register` reads the invite code from an interactive terminal or from `GYBLOS_INVITE`, never from a
command-line argument. It asks before it signs and submits a devnet registration that costs SOL, and it
doesn't change `config.toml` or publish. Read [Register and publish](/en/sellers/register-publish) before
you run it.

`seller rpc` shows the origin of the Solana RPC the seller uses. `seller rpc set` asks for the URL on an
interactive terminal (a script without one sets `GYBLOS_RPC_URL`), never takes it as an argument, saves it only after it answers as
devnet, and changes nothing else; `seller rpc reset` goes back to the public devnet RPC. The seller reads
it at startup, so restart it afterwards with `gyblos seller service restart` (see [Change the RPC of an installed seller](/en/sellers/beta-guide#change-rpc)).

## seller verify github [#verify-github]

`seller verify github USER` shows buyers which GitHub account runs this seller. The index must already know the
seller: registered, or with a catalog the index still keeps from publishing its models. It needs a gist owned by `USER` with a file named `gyblos-proof.txt` that contains the line `gyblos-node=NODEID` (an unlisted gist works too; its id is published anyway); the node key then signs a claim naming the account and the gist, and the index checks
the gist itself. If the GitHub CLI (`gh`) is signed in as `USER`, the command creates the gist. Otherwise
it prints the text to put in a file named `gyblos-proof.txt` in a new gist at gist.github.com and asks for the gist's address, or
takes it from `--gist`. A gist owned by another account is refused.

It saves its progress in the seller home and checks the index and the gist first on every run, so you can
stop it at any point and run it again. `Verified` exits 0; `pending` or `lost` exits 1 and says why, for
example that the proof line is missing or that the index could not reach GitHub (run it again later).
`--status` shows what the index holds; `--cancel` removes the link and leaves the gist for you to delete.
Only `verified` means the index found the proof.

## seller init [#init-flags-for-a-native-checkout]

`gyblos seller init` writes a starting `config.toml` with one free devnet offer. It doesn't install Docker,
create keys, download models or start an engine. The installer writes its own `config.toml`, so you need
`seller init` only for a source checkout or a hand-made setup. For the Docker seller, edit the host file
instead: the container mounts the configuration read-only.

| Flag                                 | Meaning and default                                                                                                |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| `--engine ollama\|openai\|anthropic` | Engine kind; default `ollama`                                                                                      |
| `--url URL`                          | Default Ollama `http://127.0.0.1:11435`; OpenAI `https://api.openai.com/v1`; Anthropic `https://api.anthropic.com` |
| `--model ID`                         | Default `qwen3:0.6b` for Ollama; required, or asked, for remote engines                                            |
| `--upstream-model NAME`              | The engine's name for the model; defaults to the offered model                                                     |
| `--context-tokens N`                 | Required, or asked, for OpenAI and Anthropic; omit for Ollama                                                      |
| `--api-key-env NAME`                 | Name of the API key variable; defaults `OPENAI_API_KEY` or `ANTHROPIC_API_KEY`                                     |
| `--api-key-env none`                 | No API key, for OpenAI only                                                                                        |
| `--daily-cap N`                      | Default `200000` tokens                                                                                            |
| `--per-buyer-cap N`                  | Default `50000` tokens                                                                                             |
| `--publish` / `--no-publish`         | Publication; default off; use one or the other                                                                     |
| `--force`                            | Replace an existing regular file; never follows a symlink                                                          |

On a terminal it asks for missing choices; a script gets the flags and defaults. Without `--force` it
refuses to replace an existing file. It checks the settings with a placeholder credential, so it doesn't
prove that your API key works. Its default Ollama port, `11435`, differs from the installers, which use
`11434`.

## Background service [#native-background-services]

`gyblos seller service install` runs a native seller in the background as the account that installs it:
a user systemd unit on Linux, a launch agent on macOS, or a scheduled task at logon on Windows (packaged
release only). Run it as the seller's account, never as root, and never inside the Docker container. The
installer runs it for you.

- Before it installs, it runs `doctor` with the service's own environment and refuses a seller that
  could not start.
- The service reads only the home's `seller.env` (strict `NAME=value` lines, owner-only permissions), plus
  the home and configuration paths captured at install time. It doesn't inherit your shell's variables.
- `--memory` defaults to `2048M`, which is also the minimum. `--cpu` defaults to `100%`. Only Linux
  enforces these limits.
- `--dry-run` shows what it would do without installing.
- `uninstall` stops the seller and removes the service. It keeps keys and configuration.

## logs [#local-operational-logs]

```sh
gyblos logs --role buyer
gyblos logs --role buyer --follow --level error
gyblos logs --role buyer --json --component buyer-http --operation chat
```

`gyblos logs` reads the local, content-free diagnostic log of a role. It never starts a node or contacts
a service. The local buyer writes this log. The seller records a static code for failed attempts
after peer and concurrency checks, including channel preparation, first opening and renewal.
A simulation failure describes that attempt only. Check confirmed chain state and local recovery
status before retrying.

In Docker, read the seller's channel diagnostics with `docker compose exec seller gyblos logs`.
Other seller output goes to the service log (`docker compose logs seller`, `service.log` in the
home, or `journalctl --user -u gyblos-seller`).

| Option                                                        | Meaning                                                     |
| ------------------------------------------------------------- | ----------------------------------------------------------- |
| `--role buyer\|seller`                                        | Whose log to read; default `seller`                         |
| `--level debug\|info\|warn\|error`                            | Minimum severity                                            |
| `--component NAME`, `--operation NAME`, `--correlation-id ID` | Filters                                                     |
| `--limit N`                                                   | 1 to 1000 records; default 100                              |
| `--follow`                                                    | After the last records, keep printing new ones until Ctrl+C |
| `--json`                                                      | Print the same records as JSON lines                        |

A missing log is an empty result, not an error. Logs are bounded and stay on the machine; a missing
record doesn't prove that nothing failed. Unreadable or unsafe data exits with `DIAGNOSTICS_UNAVAILABLE`.

## Installer commands [#installer-commands]

Run the installer again from where you saved it:

| Command                   | What it does                                                                       |
| ------------------------- | ---------------------------------------------------------------------------------- |
| `sh install.sh`           | Install or update the seller; on a terminal it then offers to register and publish |
| `sh install.sh publish`   | List the installed seller in the discovery index (after registering it)            |
| `sh install.sh unpublish` | Withdraw it from the index; it keeps running                                       |
| `sh install.sh update`    | Download the latest release's installer, check it and run it                       |

On Windows, run the same subcommands with
`powershell -ExecutionPolicy Bypass -File install.ps1 SUBCOMMAND`.

The installer reads these optional variables:

| Variable                     | Meaning                                                                                             |
| ---------------------------- | --------------------------------------------------------------------------------------------------- |
| `GYBLOS_MODE`                | `docker` or `native` (`install.sh` only); default: the existing install's, else Docker when it runs |
| `GYBLOS_DIR`                 | `install.sh` only: Docker seller folder; default `~/gyblos-seller`                                  |
| `GYBLOS_HOME`                | Native seller home; default `~/.gyblos` (Windows: `%USERPROFILE%\.gyblos`)                          |
| `GYBLOS_IMAGE`               | `install.sh` only: seller image; default the release pinned in the installer                        |
| `GYBLOS_RELAY_TOKEN`         | Only for a relay that requires a token                                                              |
| `GYBLOS_REQUIRE_SIGNATURE=1` | Stop unless cosign verifies the release signature                                                   |
| `GYBLOS_GUIDED=0`            | Print the steps to register and publish instead of asking                                           |
| `GYBLOS_MODIFY_PATH=0`       | `install.ps1` only: don't add `gyblos` to your user `PATH`                                          |
| `GYBLOS_RELEASE_URL`         | `install.ps1` only: where to download releases from; the checksum still applies                     |
