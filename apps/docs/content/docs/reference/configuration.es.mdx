El nodo vendedor lee un único `config.toml` al arrancar. Dónde está depende de cómo instalaste:

| Instalación     | Archivo                                                                                    |
| --------------- | ------------------------------------------------------------------------------------------ |
| Vendedor Docker | `~/gyblos-seller/config.toml` en el host, montado en solo lectura en `/config/config.toml` |
| Vendedor nativo | `~/.gyblos/config.toml` (Windows: `%USERPROFILE%\.gyblos\config.toml`)                     |
| Código fuente   | `GYBLOS_CONFIG`, si no `./config.toml`                                                     |

El vendedor lee el archivo solo al arrancar. Después de editarlo, revísalo y reinicia el vendedor como
explica [Operación](/es/sellers/operate).

## Ejemplo [#configuración-completa-para-docker-gratuito]

Este es el archivo que escribe el instalador: una oferta gratis, con la publicación desactivada.

```toml
version = 1

[node]
network = "devnet"

[discovery]
publish = false

[[offers]]
model = "qwen3:0.6b"
reasoning = ["off"]
engine = { kind = "ollama", url = "http://127.0.0.1:11434/" }
free = { daily_token_cap = 200000, per_buyer_cap = 50000 }
```

Conserva tu elección de publicación cuando edites otro ajuste. Para cambiar modelos y límites, consulta
[Cambia modelos y límites](/es/sellers/models-offers).

## Revisa antes de aplicar [#valida-antes-de-aplicar]

```sh
cd ~/gyblos-seller
docker compose run --rm seller gyblos config validate --config /config/config.toml
```

Espera `OK`. Si no, corrige cada código de problema en su ruta de clave. `config validate` revisa el esquema
y el entorno. `gyblos doctor` además comprueba que el vendedor puede arrancar con este archivo y prueba su
motor. Consulta la [referencia de la CLI](/es/reference/cli#valida-la-configuración-montada).

## Reglas del archivo [#formato-y-valores-predeterminados]

- `version = 1` y `[node] network = "devnet"` son obligatorios. Mainnet se rechaza con
  `MAINNET_UNSUPPORTED`.
- Las claves desconocidas fallan. El archivo puede medir como máximo 64 KiB.
- Las cantidades son enteros TOML, no decimales ni números entre comillas.

## Ajustes [#ajustes]

| Clave                     | Tipo y valor por defecto                                                                                              |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `node.network`            | Obligatoria: `"devnet"`                                                                                               |
| `discovery.publish`       | Booleano; por defecto `false`. `true` lista el vendedor en el índice de descubrimiento cuando está registrado         |
| `discovery.url`           | URL base HTTPS, o HTTP de loopback; por defecto `https://discovery.gyblos.com/v1`                                     |
| `relays.urls`             | De 1 a 8 orígenes HTTPS; por defecto `["https://na1.relay.gyblos.com/"]`; sin ruta, query, credenciales ni duplicados |
| `relays.relay_token_env`  | Nombre de la variable con un token de relay; por defecto `"GYBLOS_RELAY_TOKEN"`. Solo para un relay que exija token   |
| `transport.relay_only`    | Booleano; por defecto `false`. Llega a los compradores solo mediante un relay; no lo combines con `external_addr`     |
| `transport.bind`          | `ip:port` literal opcional para escuchar; IPv6 entre corchetes; el puerto puede ser `0`                               |
| `transport.external_addr` | `ip:port` opcional para anunciar; puerto de 1 a 65535                                                                 |
| `telemetry.file`          | Booleano; por defecto `false`. Escribe archivos privados de telemetría sin contenido en este equipo; no envía nada    |
| `diagnostics.enabled`     | Booleano; por defecto `true`. Registra diagnósticos del comprador y fallos de canal del vendedor                      |
| `diagnostics.level`       | `debug`, `info`, `warn` o `error`; por defecto `warn`                                                                 |
| `buyer.relay_only`        | Booleano; por defecto `false`. Un ajuste del comprador; el vendedor lo ignora                                         |

El esquema también acepta `node.data_dir`, `node.rpc_url` y `node.payout_wallet`, pero el vendedor se niega a
arrancar si alguna está en el archivo (`SELLER_SETTING_UNSUPPORTED`). El home del vendedor sale de
`GYBLOS_HOME`, su RPC de sus archivos de rol, y los pagos siempre van a su dueño.

El home guarda las llaves y el estado del vendedor. Es `/data` en la imagen Docker, `~/.gyblos` en el
vendedor nativo y `.local/gyblos` en el código fuente. Cambiarlo selecciona otra identidad: nunca lo cambies
para reparar una identidad perdida.

La subida al recolector de métricas no tiene clave en `config.toml`; consulta las
[variables de entorno](#variables-que-prevalecen-sobre-el-archivo) y [Datos y privacidad](/es/reference/data-and-privacy).

### Capacidad [#capacidad-del-vendedor]

Todas las claves de `[limits]` son enteros opcionales, de al menos 1, y solo se definen en el archivo:

| Clave                        | Por defecto | Máximo | Significado                                                      |
| ---------------------------- | ----------- | ------ | ---------------------------------------------------------------- |
| `max_connections`            | 8           | 64     | Conexiones abiertas de compradores                               |
| `requests_per_minute`        | 30          | 120    | Respuestas por NodeId de comprador por minuto                    |
| `global_requests_per_minute` | 256         | 1024   | Respuestas entre todos los compradores por minuto                |
| `max_free_buyers_per_day`    | 1024        | 65536  | Compradores distintos entre todas las ofertas gratis por día UTC |
| `max_sessions`               | 16          | 16     | Sesiones de pago reutilizables abiertas a la vez (no conexiones) |

`max_connections × requests_per_minute` no puede superar `global_requests_per_minute`, contando los valores por
defecto de las claves omitidas. Una solicitud es una respuesta: las llamadas de cotización, catálogo y recibo
que la rodean no cuentan. Doctor imprime los límites efectivos. Son independientes de los límites de tokens
de cada oferta.

### Ofertas [#campos-de-la-oferta]

El vendedor necesita de 1 a 32 entradas `[[offers]]`. Cada modelo puede aparecer una sola vez, alias
incluidos. Cada oferta debe pasar las comprobaciones de su motor, al menos un motor debe estar listo para que
el vendedor arranque, y solo se publican las ofertas listas.

| Campo                    | Regla                                                                                                                                                |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model`                  | ID o alias del catálogo, como `qwen3:0.6b`; un ID fuera del catálogo necesita `custom = true`                                                        |
| `custom`                 | Booleano; no puede ser `true` para un modelo del catálogo                                                                                            |
| `reasoning`              | Niveles distintos entre `off`, `low`, `medium`, `high`; por defecto los del catálogo, o `off`. El vendedor solo sirve `["off"]`                      |
| `engine.kind`            | Obligatorio: `ollama`, `openai` o `anthropic`                                                                                                        |
| `engine.url`             | URL base obligatoria; HTTPS, o HTTP para loopback o `host.docker.internal`; consulta [Motores](#compatibilidad-de-motores-al-iniciar)                |
| `engine.upstream_model`  | Nombre opcional del modelo en el proveedor, hasta 256 caracteres; por defecto `model`                                                                |
| `engine.api_key_env`     | Nombre de la variable de la API key; obligatorio para Anthropic; no puede empezar por `GYBLOS_` ni reutilizar la variable del token de relay         |
| `engine.context_tokens`  | Entero de 1024 a 2.000.000; obligatorio para OpenAI y Anthropic; con Ollama fija el contexto (por defecto 8.192, como máximo 32.768)                 |
| `free.daily_token_cap`   | Obligatorio en una oferta gratis; entero de 1 a 1.000.000.000.000; tokens de entrada más salida por día UTC                                          |
| `free.per_buyer_cap`     | El mismo rango; como máximo `daily_token_cap`                                                                                                        |
| `free.max_output_tokens` | Opcional; la respuesta más larga que puede pedir una solicitud; por defecto 4.096, como máximo 32.768, y también limitada por el contexto del modelo |

Cada oferta tiene exactamente uno de `free` o `price`. Los contadores gratis se reinician cuando el vendedor
se reinicia.

Para cobrar por una oferta, cambia `free` por `price`: `price.input_per_mtok` y `price.output_per_mtok` son
cadenas decimales en USDC de devnet por millón de tokens, con `price.currency = "USDC"`. Al menos una tarifa
debe ser positiva. No escribas signo, exponente ni ceros a la izquierda, y usa como máximo cuatro dígitos
enteros y seis decimales. Cualquier modelo puede tener precio: el comprador recuenta la familia Qwen3, y los demás
cobran el uso que informa tu proveedor, dentro de límites por bytes que revisa el comprador. Lee [Cobrar](/es/sellers/get-paid) antes de
ponerle precio a una oferta.

### Motores [#compatibilidad-de-motores-al-iniciar]

- **Ollama:**
  - el modelo fijado Qwen3 0.6B, reasoning `off` y ninguna variable de API key;
  - una URL raíz de loopback literal. Los instaladores usan `http://127.0.0.1:11434/`;
  - `localhost` o `host.docker.internal` pasan la revisión del esquema pero fallan al arrancar.
- **Compatible con OpenAI:** reasoning `off`, un tamaño de contexto explícito y una URL HTTPS o de loopback
  literal, normalmente terminada en `/v1`. Desactiva el razonamiento en el proveedor. Una API key con nombre
  debe estar definida y no vacía.
- **Compatible con Anthropic:** reasoning `off`, un tamaño de contexto y una API key no vacía. Usa la raíz de
  la API sin `/v1`; el proveedor debe admitir la consulta de modelos y Messages.

Con modelos que no sean los Qwen3 híbridos del catálogo, el vendedor informa el conteo de tokens del proveedor sin recontarlo.
Un proveedor remoto puede cobrarte y recibe los prompts de los compradores, incluso con una oferta gratis.

## Variables de entorno [#variables-que-prevalecen-sobre-el-archivo]

En los ajustes del vendedor, una variable de entorno reemplaza al archivo, y el archivo reemplaza al valor
por defecto. El vendedor Docker toma su entorno de `seller.env`; una variable definida solo en la terminal del
host no llega al contenedor. El servicio nativo también lee solo su `seller.env`. Después de editar
`seller.env`, reinicia el vendedor como explica [Operación](/es/sellers/operate).

| Variable                    | Significado                                                                                                                                                                        |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GYBLOS_CONFIG`             | El archivo que leen `start`, `doctor` y `seller init`; `config validate` usa `--config`                                                                                            |
| `GYBLOS_HOME`               | El home del vendedor (llaves y estado); fijo en `/data` en la imagen Docker                                                                                                        |
| `GYBLOS_RELAYS`             | Orígenes de relay separados por comas                                                                                                                                              |
| `GYBLOS_RELAY_TOKEN`        | Token de relay opcional, solo para un relay que lo exija; guárdalo en `seller.env`                                                                                                 |
| `GYBLOS_RELAY_ONLY`         | `1` activa el modo solo relay, `0` lo desactiva; cualquier otro valor lo desactiva con un aviso                                                                                    |
| `GYBLOS_IROH_BIND`          | Reemplaza `transport.bind`; vacía se ignora                                                                                                                                        |
| `GYBLOS_IROH_EXTERNAL_ADDR` | Reemplaza `transport.external_addr`; vacía se ignora                                                                                                                               |
| `GYBLOS_DISCOVERY_PUBLISH`  | `1` o `0` estrictos para reemplazar `discovery.publish`; cualquier otro valor es un error                                                                                          |
| `GYBLOS_DISCOVERY_URL`      | Reemplaza `discovery.url`; se comprueba cuando la publicación está activa                                                                                                          |
| `GYBLOS_OBSERVATIONS`       | `off` deja de subir observaciones de telemetría; los recibos se siguen subiendo                                                                                                    |
| `GYBLOS_COLLECTOR_URL`      | Otro recolector de métricas (HTTPS, o HTTP en loopback); cualquier otro valor desactiva la subida                                                                                  |
| `GYBLOS_UPDATE_CHECK`       | `0` impide que `gyblos seller status` busque una versión más nueva                                                                                                                 |
| `GYBLOS_INVITE`             | El código de invitación para `gyblos seller register`; nunca lo pongas en TOML ni en el historial                                                                                  |
| `GYBLOS_BUYER_RELAY_ONLY`   | Un ajuste del comprador; el vendedor lo ignora                                                                                                                                     |
| `GYBLOS_RPC_URL`            | El vendedor en marcha lo ignora, porque su archivo de rol fija el RPC; lo leen la primera ejecución del instalador y [`gyblos seller rpc set`](/es/sellers/beta-guide#cambiar-rpc) |

`[limits]`, las ofertas, `[telemetry]` y `[diagnostics]` no tienen variable de entorno.

## Secretos [#secretos-y-errores]

- En TOML, escribe el nombre de una variable (claves `*_env`), nunca una credencial.
- Los nombres de variable usan mayúsculas, dígitos y guiones bajos, y no empiezan por un dígito.
- Guarda las credenciales solo en el `seller.env` privado. Nunca reutilices un token de relay como llave de
  un proveedor.
- Un TOML con una credencial escrita, o una URL con una credencial en su query, falla con `INLINE_SECRET`.
  Una credencial escondida en la ruta de una URL puede pasar, así que revisa la salida antes de compartirla.

Los avisos de validación como `ENV_SWITCH_NOT_STRICT` y `REASONING_UNVERIFIED` no hacen fallar la revisión.
Para cada código de error y su solución, consulta
[Solución de problemas](/es/help/troubleshooting#configuración-rechazada).
