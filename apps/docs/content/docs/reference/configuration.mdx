The seller node reads one `config.toml` at startup. Where it lives depends on how you installed it:

| Install         | File                                                                                  |
| --------------- | ------------------------------------------------------------------------------------- |
| Docker seller   | `~/gyblos-seller/config.toml` on the host, mounted read-only at `/config/config.toml` |
| Native seller   | `~/.gyblos/config.toml` (Windows: `%USERPROFILE%\.gyblos\config.toml`)                |
| Source checkout | `GYBLOS_CONFIG`, otherwise `./config.toml`                                            |

The seller reads the file only when it starts. After an edit, check the file, then restart the seller as
[Operate and update](/en/sellers/operate) describes.

## Example [#complete-free-docker-configuration]

This is the file the installer writes: one free offer, with publication off.

```toml
version = 1

[node]
network = "devnet"

[discovery]
publish = false

[[offers]]
model = "qwen3:0.6b"
reasoning = ["off"]
engine = { kind = "ollama", url = "http://127.0.0.1:11434/" }
free = { daily_token_cap = 200000, per_buyer_cap = 50000 }
```

Keep your publication choice when you edit another setting. To change models and caps, see
[Change models and limits](/en/sellers/models-offers).

## Check before applying [#validate-before-applying]

```sh
cd ~/gyblos-seller
docker compose run --rm seller gyblos config validate --config /config/config.toml
```

Expect `OK`. Otherwise, fix each reported issue code at its key path. `config validate` checks the schema
and the environment. `gyblos doctor` also checks that the seller can start with this file and probes its
engine. See the [CLI reference](/en/reference/cli#validate-the-mounted-configuration).

## File rules [#file-format-and-defaults]

- `version = 1` and `[node] network = "devnet"` are required. Mainnet is refused with
  `MAINNET_UNSUPPORTED`.
- Unknown keys fail. The file can be at most 64 KiB.
- Counts are TOML integers, not floats or quoted numbers.

## Settings [#settings]

| Key                       | Type and default                                                                                                   |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `node.network`            | Required: `"devnet"`                                                                                               |
| `discovery.publish`       | Boolean; default `false`. `true` lists the seller in the discovery index once it is registered                     |
| `discovery.url`           | HTTPS, or loopback HTTP, base URL; default `https://discovery.gyblos.com/v1`                                       |
| `relays.urls`             | 1 to 8 HTTPS origins; default `["https://na1.relay.gyblos.com/"]`; no path, query, credentials or duplicates       |
| `relays.relay_token_env`  | Name of the variable holding a relay token; default `"GYBLOS_RELAY_TOKEN"`. Only for a relay that requires a token |
| `transport.relay_only`    | Boolean; default `false`. Reach buyers only through a relay; don't combine with `external_addr`                    |
| `transport.bind`          | Optional literal `ip:port` to bind; IPv6 in brackets; port may be `0`                                              |
| `transport.external_addr` | Optional `ip:port` to advertise; port 1 to 65535                                                                   |
| `telemetry.file`          | Boolean; default `false`. Writes private, content-free telemetry files on this machine; sends nothing              |
| `diagnostics.enabled`     | Boolean; default `true`. Write local diagnostics for the buyer and for failed seller payment-channel attempts      |
| `diagnostics.level`       | `debug`, `info`, `warn` or `error`; default `warn`                                                                 |
| `buyer.relay_only`        | Boolean; default `false`. A buyer setting; the seller ignores it                                                   |

The schema also accepts `node.data_dir`, `node.rpc_url` and `node.payout_wallet`, but the seller refuses
to start with any of them in the file (`SELLER_SETTING_UNSUPPORTED`). The seller's home comes from
`GYBLOS_HOME`, its RPC from its role files, and payouts always go to its owner.

The home holds the seller's keys and state. It is `/data` in the Docker image, `~/.gyblos` for the native
seller, and `.local/gyblos` in a source checkout. Changing it selects a different identity: never change
it to repair a missing identity.

Uploads to the metrics collector have no `config.toml` key; see [environment variables](#environment-overrides)
and [Data and privacy](/en/reference/data-and-privacy).

### Capacity [#seller-capacity]

All `[limits]` keys are optional integers, at least 1, and only set in the file:

| Key                          | Default | Maximum | Meaning                                                  |
| ---------------------------- | ------- | ------- | -------------------------------------------------------- |
| `max_connections`            | 8       | 64      | Open buyer connections                                   |
| `requests_per_minute`        | 30      | 120     | Answers per buyer NodeId per minute                      |
| `global_requests_per_minute` | 256     | 1024    | Answers across all buyers per minute                     |
| `max_free_buyers_per_day`    | 1024    | 65536   | Distinct buyers across all free offers per UTC day       |
| `max_sessions`               | 16      | 16      | Reusable payment sessions open at once (not connections) |

`max_connections × requests_per_minute` must not exceed `global_requests_per_minute`, counting defaults for
omitted keys. A request is one answer: the quote, catalog and receipt calls around it don't count. Doctor
prints the effective limits. They are separate from the token caps of each offer.

### Offers [#offer-fields]

The seller needs 1 to 32 `[[offers]]` entries. Each model can appear only once, aliases included. Every
offer must pass its engine's checks, at least one engine must be ready for the seller to start, and only
ready offers are published.

| Field                    | Rule                                                                                                                         |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| `model`                  | Catalog ID or alias, such as `qwen3:0.6b`; an ID outside the catalog needs `custom = true`                                   |
| `custom`                 | Boolean; must not be `true` for a catalog model                                                                              |
| `reasoning`              | Distinct levels from `off`, `low`, `medium`, `high`; defaults to the catalog's, or `off`. The seller serves `["off"]` only   |
| `engine.kind`            | Required: `ollama`, `openai` or `anthropic`                                                                                  |
| `engine.url`             | Required base URL; HTTPS, or HTTP for loopback or `host.docker.internal`; see [Engines](#engine-compatibility-at-startup)    |
| `engine.upstream_model`  | Optional provider model name, up to 256 characters; defaults to `model`                                                      |
| `engine.api_key_env`     | Name of the API key variable; required for Anthropic; must not start with `GYBLOS_` or reuse the relay-token variable        |
| `engine.context_tokens`  | Integer 1024 to 2,000,000; required for OpenAI and Anthropic; for Ollama it sets the context (default 8,192, at most 32,768) |
| `free.daily_token_cap`   | Required for a free offer; integer 1 to 1,000,000,000,000; input plus output tokens per UTC day                              |
| `free.per_buyer_cap`     | Same range; at most `daily_token_cap`                                                                                        |
| `free.max_output_tokens` | Optional; the longest answer one request may ask for; default 4,096, at most 32,768, and also bounded by the model's context |

Each offer has exactly one of `free` or `price`. Free counters reset when the seller restarts.

To charge for an offer, replace `free` with `price`: `price.input_per_mtok` and `price.output_per_mtok`
are decimal strings in devnet USDC per million tokens, with `price.currency = "USDC"`. At least one rate
must be positive. Write no sign, exponent or leading zero, and at most four integer and six decimal
digits. Any model can be priced: `qwen3:0.6b` is recounted by the buyer, other models bill the usage your
provider reports within byte limits the buyer checks. See [Get paid](/en/sellers/get-paid) before you price an offer.

### Engines [#engine-compatibility-at-startup]

- **Ollama:**
  - the pinned Qwen3 0.6B model, reasoning `off`, and no API key variable;
  - a literal loopback root URL. The installers use `http://127.0.0.1:11434/`;
  - `localhost` or `host.docker.internal` pass the schema check but fail at startup.
- **OpenAI-compatible:** reasoning `off`, an explicit context size, and an HTTPS or literal loopback URL,
  usually ending in `/v1`. Turn reasoning off on the provider side. A named API key must be set and not
  empty.
- **Anthropic-compatible:** reasoning `off`, a context size and a non-empty API key. Use the API root
  without `/v1`; the provider must support model lookup and Messages.

For models other than the pinned Qwen, the seller reports the provider's token counts without recounting
them. A remote provider can charge you and receives buyers' prompts, even for a free offer.

## Environment variables [#environment-overrides]

For seller settings, an environment variable overrides the file, and the file overrides the built-in
default. The Docker seller gets its environment from `seller.env`; a variable set only in your host shell
doesn't reach the container. The native service also reads only its `seller.env`. After editing
`seller.env`, restart the seller as [Operate and update](/en/sellers/operate) describes.

| Variable                    | Meaning                                                                                                                                                            |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GYBLOS_CONFIG`             | The file `start`, `doctor` and `seller init` read; `config validate` uses `--config` instead                                                                       |
| `GYBLOS_HOME`               | The seller's home (keys and state); fixed to `/data` in the Docker image                                                                                           |
| `GYBLOS_RELAYS`             | Comma-separated relay origins                                                                                                                                      |
| `GYBLOS_RELAY_TOKEN`        | Optional relay token, only for a relay that requires one; keep it in `seller.env`                                                                                  |
| `GYBLOS_RELAY_ONLY`         | `1` turns relay-only on, `0` off; any other value turns it off with a warning                                                                                      |
| `GYBLOS_IROH_BIND`          | Overrides `transport.bind`; empty is ignored                                                                                                                       |
| `GYBLOS_IROH_EXTERNAL_ADDR` | Overrides `transport.external_addr`; empty is ignored                                                                                                              |
| `GYBLOS_DISCOVERY_PUBLISH`  | Strict `1` or `0` override of `discovery.publish`; any other value is an error                                                                                     |
| `GYBLOS_DISCOVERY_URL`      | Overrides `discovery.url`; checked when publication is on                                                                                                          |
| `GYBLOS_OBSERVATIONS`       | `off` stops uploading telemetry observations; receipts still upload                                                                                                |
| `GYBLOS_COLLECTOR_URL`      | Another metrics collector (HTTPS, or HTTP on loopback); any other value turns uploading off                                                                        |
| `GYBLOS_UPDATE_CHECK`       | `0` stops `gyblos seller status` from checking for a newer release                                                                                                 |
| `GYBLOS_INVITE`             | The invite code for `gyblos seller register`; never put it in TOML or shell history                                                                                |
| `GYBLOS_BUYER_RELAY_ONLY`   | A buyer setting; the seller ignores it                                                                                                                             |
| `GYBLOS_RPC_URL`            | Ignored by the running seller, whose role file sets the RPC; read by the installer's first run and by [`gyblos seller rpc set`](/en/sellers/beta-guide#change-rpc) |

`[limits]`, offers, `[telemetry]` and `[diagnostics]` have no environment override.

## Secrets [#secrets-and-errors]

- In TOML, write the name of a variable (`*_env` keys), never a credential.
- Variable names use uppercase letters, digits and underscores, and don't start with a digit.
- Keep credentials only in the private `seller.env`. Never reuse a relay token as a provider key.
- TOML with an inline credential, or a URL with a credential in its query, fails with `INLINE_SECRET`.
  A credential hidden in a URL path can slip through, so review the output before you share it.

Validation warnings such as `ENV_SWITCH_NOT_STRICT` and `REASONING_UNVERIFIED` don't fail the check. For
each error code and its fix, see [Troubleshooting](/en/help/troubleshooting#configuration-rejected).
