---
title: Use Gyblos from your code
description: Run the local buyer and point OpenAI or Anthropic clients at it to chat with a Gyblos seller.
---

The buyer is a small server on your own computer, at `http://127.0.0.1:4031`. It speaks the OpenAI and
Anthropic APIs, so programs written for those services can use a Gyblos seller by changing their base URL.
For each request it gets a signed free quote from the seller and streams the answer back over a direct
peer-to-peer connection.

The Responses route currently refuses `parallel_tool_calls: false`, non-default sampling, and non-neutral reasoning before contacting a seller. The signed protocol cannot carry those constraints yet; Codex versions that require them are not compatible until that support lands. Disable HTTP and stream retries in any configured client.

## What works today [#what-works-today]

| Feature                                                              | Beta status                             |
| -------------------------------------------------------------------- | --------------------------------------- |
| Whole conversations: system message, history, new message            | Yes, up to 1024 messages                |
| OpenAI `POST /v1/chat/completions` and Anthropic `POST /v1/messages` | Yes, whole answers and streaming        |
| OpenAI `POST /v1/responses` (Codex CLI)                              | Yes, whole answers and streaming        |
| `GET /v1/models`                                                     | Yes, every model your buyer serves      |
| Free offers                                                          | Yes                                     |
| Tools (function calling), both formats, whole answers and streaming  | Yes, see [Tools](#tools)                |
| Claude Code                                                          | Only with a seller on a larger model    |
| Cursor agent mode                                                    | No: it calls from Cursor's cloud        |
| Images, structured output, several answers                           | Not yet: refused with a clear 400 error |
| Paid offers                                                          | Outside this guide                      |

A seller serves each buyer up to **30 answers per minute** by default. An answer is at most **4096
tokens** unless you raise the buyer's limit (up to 32768); a longer request is served up to that limit and
ends with finish reason `length`.

Your prompt reaches the seller you configured, whose machine runs the model and can read it. Do not send
passwords, keys or other secrets.

## Before you start [#before-you-start]

- An invitation with a private **relay token**.
- The **NodeId** and **owner wallet** of the seller you will use, from a source you trust (the seller
  prints both with `gyblos doctor`). The seller must be registered; the buyer checks its identity on
  Solana devnet.
- Git, [Node.js](https://nodejs.org) 24.22.1 or later, and pnpm 10 (`corepack enable` provides it).

In the beta the buyer runs from the source repository; the installer and the npm package contain the
seller only.

## Install and configure [#install-and-configure]

```sh
git clone https://github.com/Gyblos/gyblos-node.git
cd gyblos-node
pnpm install --frozen-lockfile
pnpm buyer:init
```

`buyer:init` asks for the seller's NodeId and owner wallet, shows the settings (model `qwen3-0.6b`,
answers up to 4096 tokens, free quotes only) and saves them after you confirm. It sends nothing to the
seller or the chain. `pnpm buyer:init --advanced` also sets the model, the answer limit and the endpoints.

## Start the buyer [#start-the-buyer]

Type the relay token without showing it, then start the buyer in the same terminal:

```sh
read -rs GYBLOS_RELAY_TOKEN && export GYBLOS_RELAY_TOKEN
pnpm buyer:free
```

Leave it running. In another terminal, check that it answers:

```sh
curl http://127.0.0.1:4031/v1/models
```

The list names the one model your buyer asks for; use that name as `model` in your requests. For a quick
conversation in the terminal instead, run `pnpm buyer:chat`, which starts its own buyer.

## Send a conversation [#send-a-conversation]

```sh
curl http://127.0.0.1:4031/v1/chat/completions \
  -H 'content-type: application/json' \
  -d '{
    "model": "qwen3-0.6b",
    "messages": [
      {"role": "system", "content": "Answer in one short sentence."},
      {"role": "user", "content": "My name is Ana."},
      {"role": "assistant", "content": "Nice to meet you, Ana!"},
      {"role": "user", "content": "What is my name?"}
    ]
  }'
```

### OpenAI SDK [#openai-sdk]

Use base URL `http://127.0.0.1:4031/v1`. The free buyer does not check the API key, but the SDK needs a
non-empty one.

```js
import OpenAI from 'openai';

const client = new OpenAI({
  baseURL: 'http://127.0.0.1:4031/v1',
  apiKey: 'local',
  maxRetries: 0,
});
const stream = await client.chat.completions.create({
  model: 'qwen3-0.6b',
  stream: true,
  messages: [
    { role: 'system', content: 'Be brief.' },
    { role: 'user', content: 'My dog is called Rocky.' },
    { role: 'assistant', content: 'Got it: your dog is Rocky.' },
    { role: 'user', content: "What is my dog's name?" },
  ],
});
for await (const chunk of stream)
  process.stdout.write(chunk.choices[0]?.delta?.content ?? '');
```

### Anthropic SDK [#anthropic-sdk]

Use base URL `http://127.0.0.1:4031` (without `/v1`). `max_tokens` is required, as with Anthropic.

```js
import Anthropic from '@anthropic-ai/sdk';

const client = new Anthropic({
  baseURL: 'http://127.0.0.1:4031',
  apiKey: 'local',
  maxRetries: 0,
});
const message = await client.messages.create({
  model: 'qwen3-0.6b',
  max_tokens: 200,
  system: 'Be brief.',
  messages: [
    { role: 'user', content: 'My dog is called Rocky.' },
    { role: 'assistant', content: 'Got it: your dog is Rocky.' },
    { role: 'user', content: "What is my dog's name?" },
  ],
});
console.log(message.content[0].text);
```

## Tools [#tools]

Send `tools` as each API defines them. When the model wants a tool, the answer ends with
`finish_reason: "tool_calls"` (Anthropic: `stop_reason: "tool_use"`) and carries the call. Your program
runs the tool and sends the result back in the next request, with the whole conversation:

```js
import OpenAI from 'openai';

const client = new OpenAI({
  baseURL: 'http://127.0.0.1:4031/v1',
  apiKey: 'local',
  maxRetries: 0,
});
const tools = [
  {
    type: 'function',
    function: {
      name: 'get_time',
      description: 'Current local time in a city',
      parameters: {
        type: 'object',
        properties: { city: { type: 'string' } },
        required: ['city'],
      },
    },
  },
];
const messages = [
  { role: 'user', content: 'What time is it in Santiago? Use the tool.' },
];
const first = await client.chat.completions.create({
  model: 'qwen3-0.6b',
  messages,
  tools,
});
const call = first.choices[0].message.tool_calls[0];
// Run the tool yourself, then send its result back.
messages.push(first.choices[0].message, {
  role: 'tool',
  tool_call_id: call.id,
  content: '15:42',
});
const second = await client.chat.completions.create({
  model: 'qwen3-0.6b',
  messages,
  tools,
});
console.log(second.choices[0].message.content);
```

With the Anthropic SDK, send `tools` with `input_schema`, read the `tool_use` blocks and answer with
`tool_result` blocks, as with Anthropic. The buyer asks only sellers that serve tools; if none does, it
answers 503 and says so.

The default model, qwen3:0.6b, handles simple calls like this one. Agents that send many tools and long
instructions, such as Claude Code, need a seller on a larger model through the OpenAI or Anthropic engine.

## Switch models [#switch-models]

One buyer can serve several models by name. List them in `selection.json` under `models`; the list must
include the model in `request.selection`. A client switches by sending another name as `model` (`/model`
in most agents). Each request carries the whole conversation, so the next model reads everything said
before; only the previous seller's cache is lost, so the first answer may take a little longer.

```json
"models": [
  { "id": "qwen3-0.6b", "selection": { "modelId": "qwen3-0.6b", "variant": null, "quantization": "Q4_K_M" }, "maxTokens": 2000 },
  { "id": "gpt-oss-20b", "aliases": ["gpt-oss"], "selection": { "modelId": "gpt-oss-20b", "variant": null, "quantization": null } }
]
```

A name the buyer does not serve gets a 404 that lists the ones it does. Paid modes accept only the pinned
paid model and its token limit in this list.

## If a seller drops [#if-a-seller-drops]

On `buyer:free`, if the seller drops (its connection breaks) or stalls after it got the prompt, before
any visible text reached your client, the request goes to another seller of the same model within the
same request, and you see only the answer. That covers a complete (non-streaming) answer and a streamed
tool call with no text before it; a streamed answer that already showed text is not restarted. The
prompt goes to at most three sellers, within the 180-second limit. An error the seller sends back itself
(busy, its daily limit, an engine failure) ends the request as before, so a seller cannot read prompts
it then refuses without that showing. Because the prompt may reach a second seller,
`"failover": "never"` in `selection.json` keeps each prompt on one seller; then only a prompt that was
certainly never sent moves.

Once text reached your client, a failure ends the request with an error: the answer is not restarted
elsewhere. Disable client HTTP and stream retries: a broken connection may deliver no response headers
at all.

A manual resend starts a new selection: the same seller or another one may win. Seller-attributable
failures affect its weight. Preference for the seller that answered earlier is bounded and guarantees
neither affinity nor a warm cache. These preferences apply here to free execution; paid modes retain
their channel and seller constraints.

## Connect a coding agent [#connect-a-coding-agent]

One command writes the configuration for OpenCode, pi or Codex CLI with every model your buyer serves,
changing only the `gyblos` provider and keeping a copy of the previous file. For Claude Code it prints the
variables to set in your shell. Without `--write`, it only prints.

```bash
pnpm buyer:agent opencode --write
pnpm buyer:agent pi --write
pnpm buyer:agent codex --write
pnpm buyer:agent claude
```

Then pick a Gyblos model with `/models` (OpenCode), `/model` (pi and Claude Code) or
`codex --profile gyblos`. Each request carries the whole conversation, so switching models keeps the
context.

## Options and errors [#options-and-errors]

Options that clients send by default and that do not change the answer are accepted and ignored, such as
`temperature`, `top_p`, `user`, `metadata`, `stream_options` and, in the Anthropic format, `thinking`
(thinking is always off). Options that would change it are refused unless they hold their neutral value:
`response_format` (`text`), `n` (1) and `logprobs`. These sampling hints refer to Chat Completions and
Anthropic; Responses refuses non-neutral sampling and reasoning.

`stop` (Chat Completions, a string or up to 4 strings) and `stop_sequences` (Anthropic) are honored by your
buyer: the answer ends just before the first sequence, with finish reason `stop` (Anthropic:
`stop_reason: "stop_sequence"` and the sequence in `stop_sequence`). A cut answer carries no tool calls.
The seller does not receive the sequences, so it keeps generating until its own end: a stream shows nothing
after the sequence but closes only when the seller finishes, and `usage` counts everything it generated.
Chat Completions and Anthropic refuse images. Responses substitutes a text placeholder for an
`input_image`; it does not send image content to the seller.

| Answer | Meaning                                                                                                                                                                     |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 400    | The request uses something not supported yet; the message and `param` name it.                                                                                              |
| 503    | No seller is available right now. `Retry-After` suggests when a new attempt may succeed. The clients shown here have automatic retries disabled; retrying is your decision. |
| 504    | The seller did not answer in time.                                                                                                                                          |

Errors use each API's own shape, so SDKs raise their usual exceptions.

## Clients made for OpenRouter [#clients-made-for-openrouter]

OpenRouter speaks the same Chat Completions format, plus a few fields of its own. A client or agent set up
for OpenRouter works by pointing its base URL at your buyer (`http://127.0.0.1:<port>/v1`) and using its
token as the API key:

- `provider`, `route`, `transforms`, `usage`, `debug`, `reasoning`, `verbosity`, `prediction` and the
  extra sampling knobs `top_k`, `min_p`, `top_a` and `repetition_penalty` are accepted and ignored: they
  choose among OpenRouter's providers or tune sampling, and do not change what a seller is asked.
- `models` (a fallback list) is honored: the answer comes from the first name, `model` first, that your
  buyer serves, and the reply's `model` says which. With none served, the 404 lists the names it serves.
- OpenRouter-style names find the same model: `qwen/qwen3-0.6b` and `qwen/qwen3-0.6b:free` answer as
  `qwen3-0.6b`. The suffixes `:free`, `:nitro` and `:floor` only choose a provider there; a suffix that
  changes the answer, such as `:online` (web search), is not accepted as the plain model.
- `plugins` (for example web search) and `web_search_options` are refused with a 400 rather than skipped,
  so a client never shows an answer as searched when it was not.

Later, `provider` (a price ceiling, cheapest or fastest, sellers to avoid) could steer seller selection per
request, and `usage` could report what each answer cost; neither does yet.
