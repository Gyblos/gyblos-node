The desktop buyer starts automatically in its own private app folder (`userData` as `GYBLOS_HOME`).
It works without a relay token or choosing a folder. A fresh profile creates free-only settings
with zero budget and price ceilings, and selects a registered seller through discovery and independent
8004 verification. Existing settings and unfinished spending records are preserved.

## Download [#download]

Get the file for your system from the
[latest release](https://github.com/Gyblos/gyblos-node/releases/latest), under **Assets**:

| System                             | File                                        |
| ---------------------------------- | ------------------------------------------- |
| macOS (Apple Silicon: M1 or newer) | `gyblos-desktop-<version>-darwin-arm64.zip` |
| Windows 10/11 (x64)                | `gyblos-desktop-<version>-win32-x64.zip`    |
| Linux (Ubuntu, Debian; x64)        | `gyblos-desktop-<version>-linux-x64.deb`    |
| Other Linux (x64)                  | `gyblos-desktop-<version>-linux-x64.tar.gz` |

There is no build for Intel Macs yet. Each file has a `.sha256` next to it; to check a download, put both
in one folder and run `shasum -a 256 -c <file>.sha256` (macOS, Linux) or compare the output of
`certutil -hashfile <file> SHA256` (Windows).

## Install and open the first time [#install]

During the beta the app is **not signed** by Apple or Microsoft, so your system asks once before opening
it. This is expected; after the first time it opens normally.

### macOS [#macos]

1. Open the `.zip`, enter `Gyblos-darwin-arm64`, and drag **Gyblos.app** to **Applications**.
2. Open Gyblos. macOS says it cannot verify the developer; choose **Done**.
3. Open **System Settings → Privacy & Security**, scroll to the message about Gyblos and choose
   **Open Anyway**, then confirm with your password.
4. macOS then asks to let Gyblos use the key "Gyblos Safe Storage" in your keychain. Enter your Mac
   password and choose **Always Allow**. The app keeps its wallet protected with this key. While the
   question is open the app cannot quit and its wallet shows as unavailable.

Because the beta app is not signed, macOS asks steps 2 to 4 again after each update.

### Windows [#windows]

1. Right-click the `.zip` and choose **Extract All**.
2. Enter `gyblos-desktop-win32-x64` inside the extracted folder and open `gyblos-desktop.exe`.
3. If Windows shows "Windows protected your PC", choose **More info**, then **Run anyway**.

### Linux [#linux]

On Ubuntu or Debian, install the `.deb` and open **Gyblos** from the applications menu:

```sh
sudo apt install ./gyblos-desktop-<version>-linux-x64.deb
```

On other distributions, unpack the `.tar.gz` and run `./gyblos-desktop` inside the folder.

## Using it [#using-it]

Open **Chat**, write a message and send it. The first start prepares `buyer/` privately under the app's
own data folder, separate from the CLI or seller home. The default model is `qwen3-0.6b`; a verified,
online seller offering that model for free must be available. Discovery, the identity RPC and the
network must be reachable. An unavailable seller or network gives an error, not a simulated reply.

The answer appears as text arrives. While a response is running, the send button becomes **Stop
response**; you can also press **Esc**. Stopping keeps the partial text and does not resend the prompt.
An interrupted answer is not marked complete. A paid request whose charge is still uncertain remains
blocked for review in **Payments**; stopping does not prove that no charge occurred.

No wallet funding or transaction is required for these free answers. The local buyer identity is
separate from the protected wallet shown in Settings. A positive-price configuration or connection
still needs explicit authorization; startup never authorizes a positive budget or clears pending state.

If startup fails, **Payments → Retry local buyer** retries startup only. A failed inference is never
resent automatically. Connecting a separately running buyer remains an advanced option.

The app shows an update notice when a newer desktop build for your system is published. **View update**
opens that release on GitHub; nothing is downloaded or installed automatically. This bounded public
version check sends no identity or chat content. Offline failures stay silent; operators can disable
it with `GYBLOS_UPDATE_CHECK=0`.

The seller running the model can read your messages. Transport encryption does not hide them from
that seller. Do not send passwords, keys or other secrets.

To connect your own programs or coding agents, see [Use Gyblos from your code](/en/buyers/use-from-code).

Questions or problems? Write in the [Gyblos Telegram](https://t.me/gyblos). The group is public; do not post keys,
