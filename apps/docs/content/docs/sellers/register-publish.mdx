---
title: Register and publish
description: Register your seller with your invite code, publish its offer in the discovery index and check the listing.
---

A seller goes through three states: **running** (the seller node serves), **registered** (the discovery index
accepted its identity) and **listed** (the index publishes its offer, so buyers can find it). The installer
walks you through registering and publishing; use this page to run the steps yourself or to understand what
they do.

## Prerequisites

- A running seller ([Install a seller](/en/sellers/beta-guide)), with the keys the installer created.
- Your unused `gyb_` invite code.
- About 0.02 devnet SOL on the owner address that `gyblos doctor` prints. Registration costs about 0.01 SOL
  once; get it free from [the devnet faucet](https://faucet.solana.com). Use no mainnet funds or keys.

## 1. Register [#register-the-identity-with-discovery]

Run the command for your setup. For a Docker seller:

```sh
cd ~/gyblos-seller
docker compose exec seller gyblos seller register
```

On a native seller, run `gyblos seller register`. The command asks for your code:

```text
Invite code (from your Gyblos invitation):
```

The prompt **shows what you type**: do not share your screen or record it, and never put the code in a
command line. The command then prints the index it registers with and sends it the invite and your public
NodeId.

`Registered: this seller may now publish.` means the index accepted the registration.
`Already registered` is also a success for the same invite and keys. Registering does not change
`config.toml` and does not publish your offer.

<Callout type="warn" title="Check where your invite goes">
  The command sends your invite to `discovery.url` in `config.toml`, or to
  `GYBLOS_DISCOVERY_URL` if `seller.env` sets it. The default is
  `https://discovery.gyblos.com/v1`. If you changed either, make sure you trust
  that destination before you register.
</Callout>

### Enrollment on Solana [#complete-solana-enrollment-if-requested]

The index accepts only sellers enrolled in the **8004 agent registry** on Solana devnet, which records your
owner and NodeId on chain. If yours is not enrolled yet, the interactive command enrolls it and then retries
the index on its own:

1. It prints `Pre-simulation funding estimate:` and checks the owner's balance. If the owner has too little
   SOL, it names the owner address and how much to send, then waits and continues when the SOL arrives
   (Ctrl+C stops waiting; run the command again later).
2. It prints `Estimated registration cost:` and asks `Sign and submit this registration? (yes/no):`.
3. Answer `yes` (or `y`) to sign and submit. Any other answer stops with `REGISTER_CANCELLED`: nothing was
   signed or sent, so you can run the command again.

The estimate is not a fixed price. If the refreshed cost goes up, the command stops so you can review it
again. Without an interactive terminal, the command cannot ask for consent and stops with
`DISCOVERY_IDENTITY_NOT_REGISTERED`; run it again in a terminal. `GYBLOS_INVITE` can supply the invite code,
but never consent to an on-chain submission.

### If registration is interrupted [#if-registration-is-interrupted]

Run the same command again. The seller saves each approved registration attempt, checks it on a rerun and may print `Resending the previously approved registration.` before it sends the same signed transaction without asking again.

<Callout type="error" title="Never reset a registration">
  An uncertain result does not prove that nothing was paid. Deleting the
  seller's data, its registration file or its lock, or changing its home, can
  pay a second time or lose your identity, and cannot be undone. If the result
  stays uncertain, ask in the [Gyblos Telegram](https://t.me/gyblos).
</Callout>

### Registration errors

| Code                       | Meaning and next action                                                       |
| -------------------------- | ----------------------------------------------------------------------------- |
| `DISCOVERY_INVITE_INVALID` | The code is wrong, already used or expired. Check it or ask for a new invite. |
| `DISCOVERY_RATE_LIMITED`   | Too many attempts. Wait before trying again.                                  |
| `DISCOVERY_UNAVAILABLE`    | The index could not complete the request. Try again later.                    |

For revoked identities and other codes, see [troubleshooting](/en/help/troubleshooting).

## 2. Publish [#enable-publication]

Turn publishing on from the folder where you saved the installer:

```sh
sh install.sh publish
```

On Windows, run `powershell -ExecutionPolicy Bypass -File install.ps1 publish`. If you installed in another
folder, prefix the same `GYBLOS_DIR=…` (Docker) or `GYBLOS_HOME=…` (native) that you installed with.

Publishing sends no blockchain transaction and costs nothing. The installer sets `publish = true` in
`config.toml`, validates the file and restarts the seller. If validation fails or you interrupt it, the file
stays as it was. The index lists your seller within about two minutes, once it is registered.

To publish a Docker seller by hand, edit the existing `[discovery]` table in `~/gyblos-seller/config.toml`.
Do not add a second table:

```toml
[discovery]
publish = true
```

Then validate the file and apply it as described in
[Operate and update](/en/sellers/operate#apply-configuration-or-environment-changes).

## 3. Check the listing [#confirm-the-listing]

Ask the index whether it lists your seller. For a Docker seller:

```sh
cd ~/gyblos-seller
docker compose exec seller gyblos seller status --online
```

On a native seller, run `gyblos seller status --online`. The discovery line reports one of these:

| Observation                               | What it means                                     |
| ----------------------------------------- | ------------------------------------------------- |
| `listed in the index`                     | The index lists this NodeId for the model.        |
| `not found in the index`                  | The lookup finished and did not find this NodeId. |
| `not in the first N sellers of the index` | The lookup stopped early; the listing is unknown. |
| `index unreachable`                       | The lookup failed; the listing is unknown.        |

The index receives your public identity, model and offer, never prompts. Only offers the seller can serve
are published. A listing proves that buyers can find your seller, not that a request has completed.

## Unlist [#unlist-without-losing-your-identity]

Run `sh install.sh unpublish`. It sets `publish = false` and restarts the seller, which keeps running; the
index withdraws it within about two minutes. Stopping the seller also withdraws it within two minutes. Never
delete keys to leave discovery: a used invite code cannot register new keys.
