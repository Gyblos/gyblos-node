---
title: Install a seller
description: Install a free seller with the official installer, register it with your invite code and publish it.
---

The installer sets up a free seller node that serves Qwen3 0.6B through Ollama, then walks you through
registering and publishing it. Most of the time goes into downloading the images and the model.

## Prerequisites

- An invitation with its `gyb_` invite code. Keep the code private. You need no relay token. If you don't
  have one, ask for it in the [Gyblos Telegram](https://t.me/gyblos).
- A machine that meets the [beta requirements](/en/getting-started/beta), including memory headroom.
- One of these setups:
  - **Docker seller:** Linux, macOS or Windows with Docker and Compose v2.17 or later.
  - **Native seller:** a Mac with Apple Silicon or Linux (x64 or arm64, glibc) with your own
    [Ollama](https://ollama.com/download).
  - **Windows native seller:** Windows 10 or 11 (x64) with [Ollama for Windows](https://ollama.com/download/windows).

## 1. Run the installer [#install-the-seller]

Download the official installer, read it if you like, and run it:

```sh
curl -fsSL https://gyblos.com/install.sh -o install.sh
sh install.sh
```

With Docker running, the installer sets up a **Docker seller** in `~/gyblos-seller` (set `GYBLOS_DIR` to use
another folder). It writes `compose.yaml`, `config.toml` and a private `seller.env`, starts its own Ollama,
downloads `qwen3:0.6b`, creates the seller keys in a Docker volume, installs the tokenizer, runs
`gyblos doctor` and starts the seller.

The installer pins one signed release of the seller image by version and digest. With
[cosign](https://docs.sigstore.dev/cosign/system_config/installation/) 3 or later installed, it prints
`Verified the Gyblos release signature` before pulling. Without cosign, it says the check was skipped.
To make the check mandatory, run `GYBLOS_REQUIRE_SIGNATURE=1 sh install.sh`; it then stops unless the
signature verifies. To verify the image yourself or write each file by hand, see
[Install without the script](/en/sellers/manual-install).

### Your own devnet RPC, if you will charge [#own-rpc]

A seller that charges sends channel transactions through its Solana RPC. The default, the public
`https://api.devnet.solana.com`, needs no account and works for most sellers. It limits requests per IP
address, though, so several services on one address can make channel openings fail (`gyblos logs` then
shows `invalid_batch_settlement_svm_channel_state` or `PAYMENT_UNAVAILABLE`). Then use a dedicated devnet
endpoint: set it on an [installed seller](#change-rpc), or set `GYBLOS_RPC_URL` before the **first** run of
the installer (replace `DEVNET_RPC_URL` with your endpoint's URL):

- **Docker:** create the folder and a private `seller.env` with the URL, then run the installer in Docker
  mode, which keeps both and stops if Docker cannot run (with `GYBLOS_DIR`, use that folder):

  ```sh
  mkdir -m 700 ~/gyblos-seller
  (umask 077 && printf 'GYBLOS_RPC_URL=%s\n' 'DEVNET_RPC_URL' > ~/gyblos-seller/seller.env)
  GYBLOS_MODE=docker sh install.sh
  ```

- **Native on macOS or Linux:** `GYBLOS_RPC_URL='DEVNET_RPC_URL' GYBLOS_MODE=native sh install.sh`
  (without `GYBLOS_MODE=native`, a running Docker is chosen and the variable is not used).
- **Windows:** in PowerShell, `$env:GYBLOS_RPC_URL='DEVNET_RPC_URL'` before running `install.ps1`.

The seller keeps the URL in its private role file. A URL with an API key is a secret: never put it in
`config.toml`.

#### Change the RPC of an installed seller [#change-rpc]

`gyblos seller rpc set` asks for the URL on the terminal, checks that it answers as Solana devnet and saves
it; your keys, NodeId and registration stay. It never takes the URL as an argument, so it stays out of your
shell history, and afterwards it shows only the address, never the path or key. Use a provider you trust:
the seller's fee payer signs what this RPC asks it to. Then restart the seller:

- **Docker:** in the seller folder, `docker compose exec seller gyblos seller rpc set`, then
  `docker compose restart seller`.
- **Native on macOS, Linux or Windows:** `gyblos seller rpc set`, then `gyblos seller service restart`,
  which keeps the background service's settings. If you run `gyblos start` yourself, stop it and run it
  again.

On a terminal the command always asks for the URL. A script without one sets `GYBLOS_RPC_URL` instead.

`gyblos seller rpc` shows the RPC in use, and `gyblos seller rpc reset` goes back to the public one.

### Native seller on macOS or Linux

Without a usable Docker, the same installer sets up the **native seller**: it checks the download against
the release's checksum and signature, keeps everything in `~/.gyblos` and runs the seller as a background
service. It uses your own Ollama and never installs it. If Ollama is not running, it says how to start it;
run the script again to continue.

On a Mac with Apple Silicon, Docker cannot use the GPU, so the native seller is faster even when Docker is
installed:

```sh
GYBLOS_MODE=native sh install.sh
```

Intel Macs use Docker. On a native seller you type `gyblos …` where these guides show
`docker compose exec seller gyblos …`.

### Windows [#windows]

On Windows 10 or 11 (x64), run `install.ps1` in PowerShell instead:

```powershell
irm https://github.com/Gyblos/gyblos-node/releases/latest/download/install.ps1 -OutFile install.ps1
powershell -ExecutionPolicy Bypass -File install.ps1
```

It works like the native seller: it checks the download against the release's checksum, keeps the seller's
files in `%USERPROFILE%\.gyblos` (readable only by your account), uses your own Ollama and runs the seller in
the background while you are logged in. Open a new terminal afterwards to type `gyblos …`. Wherever these
guides say `sh install.sh`, run `powershell -ExecutionPolicy Bypass -File install.ps1`.

### Save the public identity

When the seller starts, the installer prints `The seller is running` and the public identity from doctor.
The output is similar to the following:

```text
Seller identity (public; `docker compose exec seller gyblos seller register` enrolls it in discovery):
  nodeId  NODE_ID
  owner   OWNER_ADDRESS
  fee payer  FEE_PAYER_ADDRESS  (pays channel transactions once an offer has a price; send it about 0.05 devnet SOL first)
```

These values are public and safe to share. Your seller starts **unlisted**: buyers cannot find it until you
register and publish it. What each key does is in [Identity and backups](/en/sellers/identity#keys).

Two of these addresses need devnet SOL, which is free test money from
[faucet.solana.com](https://faucet.solana.com) (choose **devnet**):

| Address     | When                               | How much                                                                    |
| ----------- | ---------------------------------- | --------------------------------------------------------------------------- |
| `owner`     | Before registering, every seller   | About 0.02 SOL; registration costs about 0.01 once                          |
| `fee payer` | Before you set a price on an offer | About 0.05 SOL; it pays the payment token accounts and channel transactions |

A free seller funds only the owner. The installer ends with the fee payer note, and `gyblos doctor --online`
flags a low fee payer balance ([Get paid](/en/sellers/get-paid#fund-the-fee-payer)).

## 2. Register and publish [#finish-onboarding]

In a terminal, the installer continues straight into registration and publishing, and asks before each
step:

1. **Register.** Paste the invite code when asked. The prompt shows what you type, so do not share your
   screen. Registration costs the owner about 0.01 devnet SOL once. Devnet SOL is free test money.
2. **Fund the owner if asked.** If the owner has too little SOL, the command prints its address and how much
   to send, then waits. Open [faucet.solana.com](https://faucet.solana.com), choose **devnet**, paste the
   owner address and request about 0.02 SOL. The command continues on its own when the SOL arrives.
3. **Confirm the registration.** Review the estimated cost and answer `y` to sign and submit it.
4. **Publish.** Press Enter (or `y`) to list your offer in the discovery index.

When both steps succeed, the installer prints:

```text
Done: this seller is registered and published. Buyers can find it within about two minutes.
```

Press Ctrl+C at any step and run `sh install.sh` again later: it keeps what is done and continues. Without a
terminal, or with `GYBLOS_GUIDED=0`, the installer only prints these steps for you to run yourself. While the
seller runs, `gyblos seller status` names the next step. The details, including what to do if registration
is interrupted, are in [Register and publish](/en/sellers/register-publish).

## 3. Check the status [#confirm-the-service-state]

For a Docker seller, run commands from the installation folder:

```sh
cd ~/gyblos-seller
docker compose exec seller gyblos seller status
```

On a native seller, run `gyblos seller status`. Its `Result:` line is one of these:

| Result          | Meaning and next action                                                        |
| --------------- | ------------------------------------------------------------------------------ |
| `RUNNING`       | The seller is serving. You are done.                                           |
| `STARTING`      | Wait briefly, then check again.                                                |
| `FAILING`       | Read the phase and error code, then follow the matching troubleshooting entry. |
| `STOPPED`       | Start it again ([Operate and update](/en/sellers/operate#stop-and-start)).     |
| `NOT_CONFIRMED` | The service state could not be confirmed. Check `docker compose ps`.           |

To confirm that the discovery index lists your seller, add `--online` (`gyblos seller status --online`). It
reports `listed in the index` once the listing is live. Without `--online`, status prints a `Next:` line
while a registration or publishing step is still missing.

## If the installation stops [#installation-issues]

Read the `FAIL` or `gyblos install:` line and look it up in [troubleshooting](/en/help/troubleshooting). Fix
the cause, then run the installer again. A rerun keeps your existing configuration, `seller.env` and keys.

If a Docker container is stopped or restarting, `exec` cannot reach it. Run the one-off diagnostic instead:

```sh
cd ~/gyblos-seller
docker compose run --rm seller gyblos doctor
```

<Callout type="error" title="Keep your keys">
  `docker compose down -v` deletes the Docker volumes, including your seller
  keys, and cannot be undone. A used invite code cannot register new keys. To
  stop the seller, run `docker compose stop seller` instead.
</Callout>

## What your seller sends

Release builds send content-free signed receipts and telemetry observations to the Gyblos metrics
collector, and `gyblos seller status` checks GitHub for a newer release. Receipts and observations never
contain prompts or answers. To turn off observations, see
[what your seller sends](/en/sellers/operate#data-your-seller-sends).
