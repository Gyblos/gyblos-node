Use this guide after checking the [beta requirements](/en/getting-started/beta).
Keep your invitation's relay token and invite code private. Downloading the images and model takes most
of the installation time; the duration depends on your connection and machine.

## Before you start

You need an invitation with `install.sh` and a private relay token, Linux or macOS,
Docker with Compose v2.17 or later, at least 4 GB of memory and outbound internet access.
Check the [full requirements](/en/getting-started/beta), including memory headroom, before installing.

## Install [#install-the-seller]

In the folder where you saved the invitation's `install.sh`, run:

```sh
sh install.sh
```

The relay token is hidden while you enter it. The script works in `~/gyblos-seller` unless you explicitly
set another installation directory. It creates `compose.yaml`, `gyblos.toml` and private `seller.env`,
downloads Ollama and `qwen3:0.6b`, creates seller keys in a Docker volume, installs the tokenizer,
runs `gyblos doctor` and starts the seller.

### Public identity

When it prints `The seller is running`, continue with the status check. Save the public identity
printed by doctor:

```text
Seller identity (public; `gyblos seller register` enrolls it in discovery):
  nodeId  4d789a89…
  owner   7is91kWV…
```

These are abbreviated examples, not keys or values to copy into configuration. Discovery registration
is separate from the on-chain enrollment that the index checks.

### Installation issues

If installation stops, read the `FAIL` or `gyblos install:` line and use
[troubleshooting](/en/help/troubleshooting). Correct the cause before rerunning the script.
Rerunning preserves existing configuration, token file and identity; it does not reset those files.

## Check status [#confirm-the-service-state]

Run commands from the installation folder:

```sh
cd ~/gyblos-seller
docker compose exec seller gyblos seller status
```

| Result          | Meaning and next action                                                   |
| --------------- | ------------------------------------------------------------------------- |
| `RUNNING`       | The service is running. Continue to registration.                         |
| `STARTING`      | Wait briefly, then check again.                                           |
| `FAILING`       | Read the phase and error code; follow the matching troubleshooting entry. |
| `STOPPED`       | Run `docker compose up -d --force-recreate seller`.                       |
| `NOT_CONFIRMED` | Check `docker compose ps`; service health could not be confirmed.         |

### Diagnostics

If the container is stopped or restarting, `exec` cannot work. Run the one-off diagnostic instead:

```sh
cd ~/gyblos-seller
docker compose run --rm seller gyblos doctor
```

Doctor success does not prove that a buyer request completed. After registration and publication,
ask the team through your invitation channel if you need help arranging a free external check.

## Next steps [#finish-onboarding]

Your node starts **unlisted**. Follow [Register and publish](/en/sellers/register-publish) to use your
invite and enable publication. If Solana enrollment is missing, interactive registration estimates its
devnet SOL cost and asks before a new signed submission; review that guide before continuing. The default offer allows 200,000 input plus output tokens per UTC day,
with 5,000 per buyer; see [Models and offers](/en/sellers/models-offers) before changing limits.

<Callout type="error" title="Preserve your identity">
  `docker compose down -v` deletes the persistent volumes and your seller keys.
  Stop with `docker compose stop seller`. Read the identity guide before moving
  or removing data.
</Callout>

**Next:** [Register and publish](/en/sellers/register-publish).
