---
title: Instala sin el script
description: Verifica tú mismo la imagen firmada del vendedor y prepara a mano el mismo vendedor Docker.
---

El [instalador](/es/sellers/beta-guide) hace todo esto por ti. Usa esta página para verificar tú mismo la
firma de la imagen o para escribir a mano cada archivo del vendedor Docker. Solo cubre el vendedor Docker; los
vendedores nativo y de Windows se instalan únicamente con el instalador.

## Requisitos previos

- Docker con Compose v2.17 o posterior, en un equipo que cumpla los [requisitos de la beta](/es/getting-started/beta).
- [cosign](https://docs.sigstore.dev/cosign/system_config/installation/) 3 o posterior, para verificar la imagen.

## 1. Encuentra la versión actual

Cada instalador fija una versión de la imagen del vendedor por versión y digest. `gyblos.com/install.sh` sirve
el instalador adjunto al último [release de GitHub](https://github.com/Gyblos/gyblos-node/releases/latest).
Lee la imagen fijada en él:

```sh
curl -fsSL https://gyblos.com/install.sh | grep '^DEFAULT_IMAGE='
```

La salida se parece a `DEFAULT_IMAGE=ghcr.io/gyblos/seller:0.1.0-beta.N@sha256:…`. En los pasos siguientes,
reemplaza `VERSION@sha256:DIGEST` por todo lo que va después de `ghcr.io/gyblos/seller:`.

## 2. Verifica la firma de la imagen

El flujo de release de Gyblos en GitHub compila y firma cada versión sin ninguna llave permanente. La firma
nombra ese flujo en una etiqueta de versión y queda registrada en el registro público de Sigstore. Verifica la
imagen:

```sh
cosign verify ghcr.io/gyblos/seller:VERSION@sha256:DIGEST \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp '^https://github\.com/Gyblos/gyblos-node/\.github/workflows/release-seller-image\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.]+)?$'
```

Una imagen verificada muestra los detalles de la firma y termina sin error.

<Callout type="error" title="No ejecutes una imagen que no se verifica">
  Si `cosign verify` falla, detente aquí y no inicies esa imagen. Informa de la
  línea de la imagen en el [Telegram de Gyblos](https://t.me/gyblos).
</Callout>

El instalador hace la misma comprobación cuando cosign está instalado y muestra `Verified the Gyblos release signature`.

## 3. Escribe los archivos

Crea una carpeta privada:

```sh
mkdir -p ~/gyblos-seller && chmod 700 ~/gyblos-seller
```

Guarda esto como `~/gyblos-seller/compose.yaml`, con tu versión en la línea `image:` del vendedor:

```yaml
# A seller with its own Ollama. Setup and use: docs/running-a-node.md#docker.
# The seller shares Ollama's network namespace because the Ollama engine accepts only a literal loopback
# URL; Ollama listens on 127.0.0.1 there and no port is published. Iroh connects outbound only.
services:
  ollama:
    image: ollama/ollama:0.40.0
    environment:
      OLLAMA_HOST: 127.0.0.1:11434
      OLLAMA_NO_CLOUD: '1'
      OLLAMA_NUM_PARALLEL: '1'
      OLLAMA_MAX_LOADED_MODELS: '1'
    volumes:
      - ollama:/root/.ollama
    restart: unless-stopped

  seller:
    image: ghcr.io/gyblos/seller:VERSION@sha256:DIGEST
    network_mode: service:ollama
    # A restarted Ollama gets a new network namespace; compose then restarts the seller into it.
    depends_on:
      ollama:
        condition: service_started
        restart: true
    # Forwards stop signals to the daemon even during startup, before it installs its own handler.
    init: true
    # GYBLOS_RELAY_TOKEN and any api_key_env variables, NAME=value per line; keep it private.
    env_file:
      - ./seller.env
    volumes:
      - gyblos:/data
      - type: bind
        source: ./config.toml
        target: /config/config.toml
        read_only: true
        bind:
          create_host_path: false
    # Startup needs 1.5 GiB of memory headroom above the seller itself.
    mem_limit: 2g
    cpus: 1.0
    stop_grace_period: 120s
    restart: unless-stopped

volumes:
  ollama:
  gyblos:
```

Guarda esto como `~/gyblos-seller/config.toml`:

```toml
# The seller daemon in Docker (compose.yaml): the pinned Qwen3 0.6B with reasoning off on the compose
# Ollama, given away free within daily token caps. Copy it next to compose.yaml as config.toml; the seller
# shares Ollama's network namespace, so 127.0.0.1:11434 is that Ollama (docs/running-a-node.md#docker).
# Free by default. To charge, give an offer `price = {...}` instead of `free` (docs/configuration.md) and
# fund the fee payer `gyblos doctor` prints with devnet SOL.

version = 1

[node]
network = "devnet"

[discovery]
# Off so a test node is not listed by accident; set publish = true to appear in discovery.
publish = false

# Optional capacity limits; omitted keys keep these defaults (docs/configuration.md#seller-limits).
# [limits]
# max_connections = 8
# requests_per_minute = 30

[[offers]]
model = "qwen3:0.6b"
reasoning = ["off"]
engine = { kind = "ollama", url = "http://127.0.0.1:11434/" }
free = { daily_token_cap = 200000, per_buyer_cap = 50000 }
```

Son los mismos archivos que escribe el instalador; sus comentarios apuntan a documentos del repositorio. La
publicación empieza desactivada, para que el vendedor no aparezca listado por accidente.

Crea un `~/gyblos-seller/seller.env` vacío que solo tú puedas leer. Compose necesita el archivo, pero puede
quedar vacío: los relays de Gyblos no piden token.

```sh
(umask 077; touch ~/gyblos-seller/seller.env)
```

Solo si una oferta usa una variable `api_key_env`, añádela a `seller.env` en un editor privado como
`NAME=value`, una por línea, sin espacios, comillas ni caracteres de shell como `$` o `#`. Nunca muestres ese
archivo ni lo pegues en un comando de terminal.

## 4. Descarga, prepara e inicia

Ejecuta estos comandos desde la carpeta. Descargan las imágenes, inician Ollama, esperan a que responda y
descargan el modelo:

```sh
cd ~/gyblos-seller
docker compose pull
docker compose up -d ollama
until docker compose exec -T ollama ollama list >/dev/null 2>&1; do sleep 2; done
docker compose exec -T ollama ollama pull qwen3:0.6b
```

Si la línea de espera no termina, detenla con Ctrl+C y lee `docker compose logs ollama` en privado.

Después crea las llaves del vendedor, instala el tokenizador e inicia el vendedor cuando doctor lo apruebe. El
valor de `--mint` es el mint público de USDC de devnet; no es un secreto, así que déjalo tal cual:

```sh
docker compose run --rm seller setup --role seller --mint 4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU
docker compose run --rm seller tokenizer
docker compose run --rm seller gyblos doctor && docker compose up -d --force-recreate seller
```

La última línea inicia el vendedor solo si `gyblos doctor` no informa fallos. Doctor muestra la identidad
pública (`Seller identity (public; …`) y termina con `Result: READY`. Si informa un fallo, corrige la causa
indicada y vuelve a ejecutar esa línea.

## 5. Comprueba

Comprueba que el vendedor está en marcha:

```sh
docker compose exec seller gyblos seller status
```

Muestra `Result: RUNNING`. Continúa con [Registra y publica](/es/sellers/register-publish).
