---
title: Install without the script
description: Verify the signed seller image yourself and set up the same Docker seller by hand.
---

The [installer](/en/sellers/beta-guide) does all of this for you. Use this page to verify the image
signature yourself, or to write each file of the Docker seller by hand. This page covers the Docker seller
only; the native and Windows sellers install only through the installer.

## Prerequisites

- Docker with Compose v2.17 or later, on a machine that meets the [beta requirements](/en/getting-started/beta).
- [cosign](https://docs.sigstore.dev/cosign/system_config/installation/) 3 or later, to verify the image.

## 1. Find the current release

Each installer pins one release of the seller image by version and digest. `gyblos.com/install.sh` serves
the installer attached to the latest [GitHub release](https://github.com/Gyblos/gyblos-node/releases/latest).
Read the pinned image from it:

```sh
curl -fsSL https://gyblos.com/install.sh | grep '^DEFAULT_IMAGE='
```

The output is similar to `DEFAULT_IMAGE=ghcr.io/gyblos/seller:0.1.0-beta.N@sha256:…`. In the steps below,
replace `VERSION@sha256:DIGEST` with everything after `ghcr.io/gyblos/seller:`.

## 2. Verify the image signature

The Gyblos release workflow on GitHub builds and signs every release with no long-lived key. The signature
names that workflow at a version tag and is recorded in the public Sigstore log. Verify the image:

```sh
cosign verify ghcr.io/gyblos/seller:VERSION@sha256:DIGEST \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp '^https://github\.com/Gyblos/gyblos-node/\.github/workflows/release-seller-image\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+(-[0-9A-Za-z.]+)?$'
```

A verified image prints the signature details and exits without error.

<Callout type="error" title="Do not run an image that fails verification">
  If `cosign verify` fails, stop here and do not start that image. Report the
  image line in the [Gyblos Telegram](https://t.me/gyblos).
</Callout>

The installer runs the same check when cosign is installed and prints `Verified the Gyblos release signature`.

## 3. Write the files

Create a private folder:

```sh
mkdir -p ~/gyblos-seller && chmod 700 ~/gyblos-seller
```

Save this as `~/gyblos-seller/compose.yaml`, with your release in the seller `image:` line:

```yaml
# A seller with its own Ollama. Setup and use: docs/running-a-node.md#docker.
# The seller shares Ollama's network namespace because the Ollama engine accepts only a literal loopback
# URL; Ollama listens on 127.0.0.1 there and no port is published. Iroh connects outbound only.
services:
  ollama:
    image: ollama/ollama:0.40.0
    environment:
      OLLAMA_HOST: 127.0.0.1:11434
      OLLAMA_NO_CLOUD: '1'
      OLLAMA_NUM_PARALLEL: '1'
      OLLAMA_MAX_LOADED_MODELS: '1'
    volumes:
      - ollama:/root/.ollama
    restart: unless-stopped

  seller:
    image: ghcr.io/gyblos/seller:VERSION@sha256:DIGEST
    network_mode: service:ollama
    # A restarted Ollama gets a new network namespace; compose then restarts the seller into it.
    depends_on:
      ollama:
        condition: service_started
        restart: true
    # Forwards stop signals to the daemon even during startup, before it installs its own handler.
    init: true
    # GYBLOS_RELAY_TOKEN and any api_key_env variables, NAME=value per line; keep it private.
    env_file:
      - ./seller.env
    volumes:
      - gyblos:/data
      - type: bind
        source: ./config.toml
        target: /config/config.toml
        read_only: true
        bind:
          create_host_path: false
    # Startup needs 1.5 GiB of memory headroom above the seller itself.
    mem_limit: 2g
    cpus: 1.0
    stop_grace_period: 120s
    restart: unless-stopped

volumes:
  ollama:
  gyblos:
```

Save this as `~/gyblos-seller/config.toml`:

```toml
# The seller daemon in Docker (compose.yaml): the pinned Qwen3 0.6B with reasoning off on the compose
# Ollama, given away free within daily token caps. Copy it next to compose.yaml as config.toml; the seller
# shares Ollama's network namespace, so 127.0.0.1:11434 is that Ollama (docs/running-a-node.md#docker).
# Free by default. To charge, give an offer `price = {...}` instead of `free` (docs/configuration.md) and
# fund the fee payer `gyblos doctor` prints with devnet SOL.

version = 1

[node]
network = "devnet"

[discovery]
# Off so a test node is not listed by accident; set publish = true to appear in discovery.
publish = false

# Optional capacity limits; omitted keys keep these defaults (docs/configuration.md#seller-limits).
# [limits]
# max_connections = 8
# requests_per_minute = 30

[[offers]]
model = "qwen3:0.6b"
reasoning = ["off"]
engine = { kind = "ollama", url = "http://127.0.0.1:11434/" }
free = { daily_token_cap = 200000, per_buyer_cap = 50000 }
```

These files are the ones the installer writes; their comments point to repository documents. Publishing
starts off, so the seller is not listed by accident.

Create an empty `~/gyblos-seller/seller.env` readable only by you. Compose requires the file, but it can
stay empty: the Gyblos relays need no relay token.

```sh
(umask 077; touch ~/gyblos-seller/seller.env)
```

Only if an offer uses an `api_key_env` variable, add it to `seller.env` in a private editor as `NAME=value`,
one per line, with no spaces, quotes or shell characters such as `$` or `#`. Never print that file or paste
it into a terminal command.

## 4. Pull, prepare and start

Run these commands from the folder. They pull the images, start Ollama, wait until it answers and pull the
model:

```sh
cd ~/gyblos-seller
docker compose pull
docker compose up -d ollama
until docker compose exec -T ollama ollama list >/dev/null 2>&1; do sleep 2; done
docker compose exec -T ollama ollama pull qwen3:0.6b
```

If the wait line keeps waiting, stop it with Ctrl+C and read `docker compose logs ollama` privately.

Then create the seller keys, install the tokenizer, and start the seller once doctor passes. The `--mint`
value is the public devnet USDC mint; it is not a secret, so keep it as shown:

```sh
docker compose run --rm seller setup --role seller --mint 4zMMC9srt5Ri5X14GAgXhaHii3GnPAEERYPJgZJDncDU
docker compose run --rm seller tokenizer
docker compose run --rm seller gyblos doctor && docker compose up -d --force-recreate seller
```

The last line starts the seller only when `gyblos doctor` reports no failures. Doctor prints the public
identity (`Seller identity (public; …`) and ends with `Result: READY`. If it reports a failure, fix the named
cause and run that line again.

## 5. Verify

Check that the seller runs:

```sh
docker compose exec seller gyblos seller status
```

It prints `Result: RUNNING`. Continue with [Register and publish](/en/sellers/register-publish).
