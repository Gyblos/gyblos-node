title: Model verification
description: How Gyblos checks that a seller serves the model it declares, what pass, fail and inconclusive mean, and how anyone can repeat a check.
---

A seller declares the model it serves, for example `qwen3-1.7b`. The model verifier checks that claim from the
outside, as an ordinary buyer of your free offer. It does not read your machine, your keys or your config.

## What the verifier does [#what-it-does]

1. It asks your free offer a fixed, public set of 30 short prompts, with reasoning off and at most 200 output
   tokens each. Your free offer must allow at least 200 output tokens per request; otherwise it refuses every
   prompt and the run is inconclusive.
2. It rereads each answer with the declared model, run on the verifier's own machine. At up to 24 points per
   answer it checks that your next words are among the 20 the declared model finds most likely, with a
   probability of at least 0.1 %.
3. It counts the answers with at least one point that fails that check and signs a result with its own key.
   The points are chosen with a secret drawn for each run, after the answer arrives, and each run asks from a
   new buyer address. An empty answer, or one with no point to check, counts as unanswered.

An honest seller should pass: in Gyblos measurements the check tolerated sampling temperature and the
differences between a GPU and a CPU, while a smaller model sold as a larger one failed.

## Results [#results]

| Result         | Meaning                                                                                                                                                                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `fail`         | Enough answers had a failing point (12 of 30) that, under the assumptions measured for this rule, an honest seller would get this result less than once in 10,000 runs. It is an estimate, not a guarantee. It applies even if some prompts went unanswered. |
| `pass`         | Not a fail, every prompt was answered and at least 480 points were checked.                                                                                                                                                                                  |
| `inconclusive` | Not a fail, but a prompt went unanswered or fewer than 480 points could be checked, so the run proves nothing either way.                                                                                                                                    |

A result covers one seller, one model and one version of the prompt set. It is evidence from one verifier, not
a penalty: today it changes nothing in discovery, routing or payments.

In `evidence.json`, each prompt has a numbered outcome. Unscored outcomes
distinguish a failed quote, a failed execution or a reply that could not be
scored. Quote and execution failures record a code, not raw error details.

If the reference Ollama returns an empty, incomplete or malformed candidate list and retries do not recover, the command stops with
`REFERENCE_UNAVAILABLE` and does not issue a signed result. A complete list can contain empty display strings for
non-matching low-probability alternatives; empty alternatives that could affect a decision, or a list with no usable
token, remain reference errors. This is a reference error, not a seller verdict.

Only free offers of Qwen3 catalog models with a public Ollama tag are verified for now. Quantization is not
checked.

The prompts are public, so a `pass` is not proof against a seller that recognizes them and answers them
differently from real traffic. A seller that substitutes another model on only a few answers is not caught either: when all 30 answers are
scored and its other answers show no deviation, 11 or fewer substituted answers stay under the threshold of 12.
The threshold stays at 12 from 26 to 30 scored answers and drops below that (11 at 22 to 25), and deviations in
genuine answers count toward it too.

## Repeat a check [#reproduce]

The verifier is open source, so anyone with [Ollama](https://ollama.com) and the declared model can run the
same check against a seller and get a result they can compare. The steps to run it are in the
[model verifier design note](https://github.com/Gyblos/gyblos-node/blob/develop/docs/model-verifier.md#run-it) in the repository.

A run writes the signed result and an evidence file together in a new directory. Publication is atomic for
readers, but it does not fsync the files or directories, so an operating-system crash or power loss can still
lose the new directory or leave incomplete artifacts. If you pass `--out`, choose a path that does not already
exist. The evidence keeps the prompts, the answers and every check, plus any reply that could not be scored and
why, so someone else can review how the verdict was reached. `check` also rejects a result whose evidence counts
cannot fit the published challenge set before printing its verdict.
