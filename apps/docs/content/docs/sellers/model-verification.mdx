---
title: Model verification
description: How Gyblos checks that a seller serves the model it declares, what pass, fail and inconclusive mean, and how to reproduce a result.
---

A seller declares the model it serves, for example `qwen3-1.7b`. The model verifier checks that claim from the
outside, as an ordinary buyer of your free offer. It does not read your machine, your keys or your config.

## What the verifier does [#what-it-does]

1. It asks your free offer a fixed, public set of 30 short prompts, with reasoning off and at most 200 output
   tokens each.
2. It rereads each answer with the declared model, run on the verifier's own machine. At up to 24 points per
   answer it checks that your next words are among the 20 the declared model finds most likely, with a
   probability of at least 0.1 %.
3. It counts the points that fail that check and signs a result with its own key. The points are chosen with
   a secret drawn for each run, after the answer arrives, and each run asks from a new buyer address.

An honest seller should pass: in Gyblos measurements the check tolerated sampling temperature and the
differences between a GPU and a CPU, while a smaller model sold as a larger one failed.

## Results [#results]

| Result         | Meaning                                                                                                   |
| -------------- | --------------------------------------------------------------------------------------------------------- |
| `pass`         | Every prompt was answered, at least 480 points were checked, and too few failed to suggest another model. |
| `fail`         | So many points failed that an honest seller would get this result less than once in 10,000 runs.          |
| `inconclusive` | A prompt went unanswered or too few points could be checked, so the run proves nothing either way.        |

A result covers one seller, one model and one version of the prompt set. It is evidence from one verifier, not
a penalty: today it changes nothing in discovery, routing or payments.

Only free offers of Qwen3 catalog models with a public Ollama tag are verified for now. Quantization is not
checked.

## Reproduce a result [#reproduce]

From a checkout of the repository, with [Ollama](https://ollama.com) running and the declared model pulled
(`ollama pull qwen3:1.7b`), write the seller's public details to a file:

```json title="seller.json"
{
  "owner": "SELLER_OWNER_ADDRESS",
  "nodeId": "SELLER_NODE_ID",
  "relayUrl": "https://na1.relay.gyblos.com/",
  "directAddresses": []
}
```

Then run:

```sh
pnpm model-verifier verify --seller seller.json --model qwen3-1.7b
pnpm model-verifier check RESULT_DIRECTORY/result.json
```

`verify` prints the verdict and writes `result.json` (the signed result) and `evidence.json` (the prompts, the
answers and every check) to a new directory. `check` verifies a result's signature and prints its verdict.
`pnpm model-verifier address` prints the verifier's public address. The verifier key is created on first use in
`model-verifier/verifier.key` inside the Gyblos home directory.
