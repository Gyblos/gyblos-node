---
title: Change models and limits
description: Lower or raise your free token limits, set the answer and context length, and see which models and engines a seller can serve.
---

The installer sets up one free offer: **Qwen3 0.6B through Ollama**, with reasoning `off`. You can
[sell any other model](#sell-any-model) too. You change the offer in the `[[offers]]` entry of `config.toml`:

| Install type          | `config.toml` location              |
| --------------------- | ----------------------------------- |
| Docker seller         | `~/gyblos-seller/config.toml`       |
| Native seller         | `~/.gyblos/config.toml`             |
| Windows native seller | `%USERPROFILE%\.gyblos\config.toml` |

The seller reads the file only at startup. After every edit, validate and apply it as described in
[Operate and update](/en/sellers/operate#apply-configuration-or-environment-changes).

## Free limits [#lower-the-free-limits]

The `free` line of the offer sets how many tokens the seller gives away. This example halves the daily total
and lowers the per-buyer limit. Edit only that line and keep the rest of your file, including your
`[discovery]` setting:

```toml
version = 1

[node]
network = "devnet"

[discovery]
publish = false

[[offers]]
model = "qwen3:0.6b"
reasoning = ["off"]
engine = { kind = "ollama", url = "http://127.0.0.1:11434/" }
free = { daily_token_cap = 100000, per_buyer_cap = 2000 }
```

- `daily_token_cap` and `per_buyer_cap` are positive integers, and the per-buyer cap is no higher than the
  daily total. The installer's defaults are 200,000 and 50,000.
- Both count **input plus output** tokens per UTC day. Admission reserves the input plus the requested
  maximum output, so a request can be refused before the balance reaches zero. The unused part of the
  reservation returns when the answer ends.
- The counters live in memory and reset when the seller restarts. Per-buyer limits are best effort: someone
  can create another buyer identity.

## Answer and context length [#answer-and-context-length]

Two optional settings decide how long a request can be:

- `free.max_output_tokens` on the `free` line sets the longest answer one request may ask for. The default is
  4,096; the maximum is 32,768.
- `context_tokens` on the `engine` line sets the model's context. For Ollama the default is 8,192, and the
  range is 1,024 to 32,768.

Coding agents send prompts of thousands of tokens. To serve them, raise `context_tokens` and use a fast
machine with Apple Silicon or a GPU; a CPU-only server can be too slow for them. Each offer measures how
fast it reads prompts and declines, before receiving the prompt, requests it could not read in time, so a
slow server still serves the shorter ones. For example:

```toml
[[offers]]
model = "qwen3:0.6b"
reasoning = ["off"]
engine = { kind = "ollama", url = "http://127.0.0.1:11434/", context_tokens = 32768 }
free = { daily_token_cap = 200000, per_buyer_cap = 50000, max_output_tokens = 8192 }
```

All offer keys are in the [configuration reference](/en/reference/configuration#offer-fields).

## Models and engines [#changing-the-model-or-engine]

Changing `model` does not download a model or start an engine; the installer downloads only `qwen3:0.6b`.
An offer with `engine.kind = "ollama"` starts only with:

- the model `qwen3:0.6b`;
- a literal loopback URL such as `http://127.0.0.1:11434/`, with no API key;
- reasoning `off`.

Keep the Docker seller's URL at `http://127.0.0.1:11434/`: the seller shares a network namespace with its
own Ollama container, so a host service or another container is not reachable at that address.

## Sell any model [#sell-any-model]

You can offer any model your machine or provider serves. Two things decide how it is set up:

- **A model outside the catalog needs `custom = true`.** The catalog holds the Qwen3 family
  (`qwen3-0.6b`, `qwen3-1.7b`, `qwen3-4b`, `qwen3-8b`, `qwen3-14b`, `qwen3-32b`, `qwen3-30b-a3b`,
  `qwen3-235b-a22b`, with aliases such as `qwen3:8b`) and a few more IDs: `gpt-oss-20b`, `gpt-oss-120b`,
  `llama-3.3-70b`, `gemma-4-26b`, `deepseek-v4.1-flash`, `kimi-k3` and `glm-5.3-flash`. Any other name,
  such as `llama3.2:3b` or `gemma3:4b`, fails with `UNKNOWN_MODEL` unless the offer sets `custom = true`.
- **Ollama serves it through its OpenAI-compatible API.** Use `engine.kind = "openai"` with Ollama's `/v1`
  URL and an explicit `context_tokens`. A loopback Ollama needs no API key.

First download the model into the Ollama your seller uses:

| Install type  | Command                                                                  |
| ------------- | ------------------------------------------------------------------------ |
| Docker seller | `cd ~/gyblos-seller && docker compose exec ollama ollama pull gemma3:4b` |
| Native seller | `ollama pull gemma3:4b`                                                  |

Then add an offer:

```toml
[[offers]]
model = "gemma3:4b"
custom = true
reasoning = ["off"]
engine = { kind = "openai", url = "http://127.0.0.1:11434/v1", context_tokens = 8192 }
free = { daily_token_cap = 200000, per_buyer_cap = 50000 }
```

- `model` is the name buyers see; `engine.upstream_model` sets a different name for the engine when they
  differ.
- Pull only local models. A `-cloud` tag makes Ollama send buyers' prompts to ollama.com. The Docker seller
  blocks those tags; for a native seller, start Ollama with `OLLAMA_NO_CLOUD=1`. Check the model's license
  before you sell it.
- The Docker Ollama keeps one model in memory. With two offers it swaps models between requests, which is
  slow and can time out; give each extra model enough memory or keep one offer.
- Reasoning must be `off` on this engine. Turn thinking off in the model if it has a switch: hidden
  reasoning tokens can push a paid bill past its cap, and a bill past the cap is not paid.
- Buyers recount the tokens of catalog Qwen3 models only. For every other model, including the other
  catalog IDs, the usage is declared by the seller and capped by the text's size. Only buyers on
  0.1.0-beta.13 or later accept such an offer.
- Ollama's `qwen3:4b` and `qwen3:30b-a3b` tags are not catalog aliases: they can name builds with another
  chat template. Use the catalog ID and name the tag in `upstream_model`, for example
  `model = "qwen3-30b-a3b"` with `upstream_model = "qwen3:30b-a3b-q4_K_M"`.

<Callout type="warn" title="A free offer can still cost you money">
  A hosted model provider can charge you for every request your seller serves,
  and it receives the buyers' messages. Read its pricing and data policy before
  you enable it. Keep provider credentials in `seller.env`, never in
  `config.toml`.
</Callout>

To charge for the Qwen3 offer on devnet instead of giving it away, see [Get paid](/en/sellers/get-paid).
