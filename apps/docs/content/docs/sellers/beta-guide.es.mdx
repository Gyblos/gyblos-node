title: Instala un vendedor
description: Instala un vendedor gratuito con el instalador oficial, regístralo con tu código de invitación y publícalo.
---

El instalador prepara un nodo vendedor gratuito que sirve Qwen3 0.6B con Ollama y después te guía para
registrarlo y publicarlo. Casi todo el tiempo se va en descargar las imágenes y el modelo.

## Requisitos previos

- Una invitación con su código de invitación `gyb_`. Mantén el código en privado. No necesitas token de relay.
  Si no la tienes, pídela en el [Telegram de Gyblos](https://t.me/gyblos).
- Un equipo que cumpla los [requisitos de la beta](/es/getting-started/beta), incluido el margen de memoria.
- Una de estas opciones:
  - **Vendedor Docker:** Linux, macOS o Windows con Docker y Compose v2.17 o posterior.
  - **Vendedor nativo:** un Mac con Apple Silicon o Linux (x64 o arm64, glibc) con tu propio
    [Ollama](https://ollama.com/download).
  - **Vendedor nativo en Windows:** Windows 10 u 11 (x64) con [Ollama para Windows](https://ollama.com/download/windows).

## 1. Ejecuta el instalador [#instala-el-vendedor]

Descarga el instalador oficial, léelo si quieres y ejecútalo:

```sh
curl -fsSL https://gyblos.com/install.sh -o install.sh
sh install.sh
```

Si Docker está en marcha, el instalador prepara un **vendedor Docker** en `~/gyblos-seller` (usa `GYBLOS_DIR`
para elegir otra carpeta). Escribe `compose.yaml`, `config.toml` y un `seller.env` privado, inicia su propio
Ollama, descarga `qwen3:0.6b`, crea las llaves del vendedor en un volumen de Docker, instala el tokenizador,
ejecuta `gyblos doctor` e inicia el vendedor.

El instalador fija una versión firmada de la imagen del vendedor por versión y digest. Si tienes
[cosign](https://docs.sigstore.dev/cosign/system_config/installation/) 3 o posterior, muestra
`Verified the Gyblos release signature` antes de descargarla. Sin cosign, avisa de que omitió la comprobación.
Para que la comprobación sea obligatoria, ejecuta `GYBLOS_REQUIRE_SIGNATURE=1 sh install.sh`: se detiene si la
firma no se verifica. Para verificar la imagen tú mismo o escribir cada archivo a mano, consulta
[Instala sin el script](/es/sellers/manual-install).

### Tu propio RPC de devnet, si vas a cobrar [#rpc-propio]

Un vendedor que cobra envía las transacciones del canal por su RPC de Solana. El predeterminado, el
público `https://api.devnet.solana.com`, no necesita cuenta y sirve para la mayoría de los vendedores. Pero
limita las solicitudes por dirección IP, así que varios servicios en una misma dirección pueden hacer fallar
las aperturas de canal (`gyblos logs` muestra entonces `invalid_batch_settlement_svm_channel_state` o
`PAYMENT_UNAVAILABLE`). En ese caso usa un endpoint de devnet propio: cámbialo en un
[vendedor instalado](#cambiar-rpc), o define `GYBLOS_RPC_URL` antes de ejecutar el instalador por
**primera** vez (reemplaza `DEVNET_RPC_URL` por la URL de tu endpoint):

- **Docker:** crea la carpeta y un `seller.env` privado con la URL, y luego ejecuta el instalador en modo
  Docker, que conserva ambos y se detiene si Docker no puede correr (con `GYBLOS_DIR`, usa esa carpeta):

  ```sh
  mkdir -m 700 ~/gyblos-seller
  (umask 077 && printf 'GYBLOS_RPC_URL=%s\n' 'DEVNET_RPC_URL' > ~/gyblos-seller/seller.env)
  GYBLOS_MODE=docker sh install.sh
  ```

- **Nativo en macOS o Linux:** `GYBLOS_RPC_URL='DEVNET_RPC_URL' GYBLOS_MODE=native sh install.sh`
  (sin `GYBLOS_MODE=native`, si Docker está en marcha se elige Docker y la variable no se usa).
- **Windows:** en PowerShell, `$env:GYBLOS_RPC_URL='DEVNET_RPC_URL'` antes de ejecutar
  `install.ps1`.

El vendedor guarda la URL en su archivo de rol privado. Una URL con clave de API es un secreto: nunca la
pongas en `config.toml`.

#### Cambiar el RPC de un vendedor instalado [#cambiar-rpc]

`gyblos seller rpc set` pide la URL en la terminal, comprueba que responda como Solana devnet y la guarda;
tus llaves, tu NodeId y tu registro no cambian. Nunca recibe la URL como argumento, así no queda en el
historial de la terminal, y después solo muestra la dirección, nunca la ruta ni la clave. Usa un proveedor
de confianza: el pagador de comisiones del vendedor firma lo que este RPC le pide. Después reinicia el
vendedor:

- **Docker:** en la carpeta del vendedor, `docker compose exec seller gyblos seller rpc set`, y luego
  `docker compose restart seller`.
- **Nativo en macOS, Linux o Windows:** `gyblos seller rpc set`, y luego ejecuta el comando de reinicio que
  muestra (`launchctl` en macOS, `systemctl --user` en Linux, `schtasks` en Windows), que conserva los
  ajustes del servicio en segundo plano. Si corres `gyblos start` tú mismo, detenlo y vuelve a ejecutarlo.

Si `GYBLOS_RPC_URL` (por ejemplo en el `seller.env` de Docker) todavía tiene el RPC que usa el vendedor, el
comando pide el nuevo en la terminal.

`gyblos seller rpc` muestra el RPC en uso, y `gyblos seller rpc reset` vuelve al público.

### Vendedor nativo en macOS o Linux

Si no hay un Docker utilizable, el mismo instalador prepara el **vendedor nativo**: comprueba la descarga con
la suma de verificación y la firma del release, guarda todo en `~/.gyblos` y deja el vendedor como servicio en
segundo plano. Usa tu propio Ollama y nunca lo instala. Si Ollama no está en marcha, te dice cómo iniciarlo;
vuelve a ejecutar el script para continuar.

En un Mac con Apple Silicon, Docker no puede usar la GPU, así que el vendedor nativo es más rápido aunque
tengas Docker:

```sh
GYBLOS_MODE=native sh install.sh
```

Los Mac con Intel usan Docker. En un vendedor nativo escribes `gyblos …` donde estas guías muestran
`docker compose exec seller gyblos …`.

### Windows [#windows]

En Windows 10 u 11 (x64), ejecuta `install.ps1` en PowerShell:

```powershell
irm https://github.com/Gyblos/gyblos-node/releases/latest/download/install.ps1 -OutFile install.ps1
powershell -ExecutionPolicy Bypass -File install.ps1
```

Funciona como el vendedor nativo: comprueba la descarga con la suma de verificación del release, guarda los
archivos del vendedor en `%USERPROFILE%\.gyblos` (solo tu cuenta puede leerlos), usa tu propio Ollama y deja
el vendedor en segundo plano mientras tienes la sesión iniciada. Después abre una terminal nueva para escribir
`gyblos …`. Donde estas guías digan `sh install.sh`, ejecuta `powershell -ExecutionPolicy Bypass -File install.ps1`.

### Guarda la identidad pública

Cuando el vendedor arranca, el instalador muestra `The seller is running` y la identidad pública que imprime
doctor. La salida se parece a esta:

```text
Seller identity (public; `docker compose exec seller gyblos seller register` enrolls it in discovery):
  nodeId  NODE_ID
  owner   OWNER_ADDRESS
  fee payer  FEE_PAYER_ADDRESS  (pays channel transactions once an offer has a price; send it about 0.05 devnet SOL first)
```

Estos valores son públicos y puedes compartirlos. Tu vendedor empieza **sin publicar**: los compradores no lo
encuentran hasta que lo registras y lo publicas. Qué hace cada llave está en
[Identidad y copias de seguridad](/es/sellers/identity#llaves).

Dos de estas direcciones necesitan SOL de devnet, que es dinero de prueba gratis de
[faucet.solana.com](https://faucet.solana.com) (elige **devnet**):

| Dirección   | Cuándo                               | Cuánto                                                                              |
| ----------- | ------------------------------------ | ----------------------------------------------------------------------------------- |
| `owner`     | Antes de registrar, todo vendedor    | Unos 0,02 SOL; el registro cuesta unos 0,01 una sola vez                            |
| `fee payer` | Antes de ponerle precio a una oferta | Unos 0,05 SOL; paga las cuentas de token de pago y las transacciones de los canales |

Un vendedor gratuito solo necesita SOL en el owner. El instalador termina con el aviso del fee payer, y
`gyblos doctor --online` señala si el saldo del fee payer es bajo ([Cobra](/es/sellers/get-paid#carga-el-pagador-de-comisiones)).

## 2. Registra y publica [#completa-el-alta]

En una terminal, el instalador pasa directamente al registro y la publicación, y pregunta antes de cada paso:

1. **Registra.** Pega el código de invitación cuando te lo pida. El campo muestra lo que escribes, así que no
   compartas tu pantalla. El registro le cuesta al dueño (`owner`) unos 0,01 SOL de devnet una sola vez. El SOL
   de devnet es dinero de prueba y es gratis.
2. **Carga al dueño si te lo pide.** Si el dueño no tiene SOL suficiente, el comando muestra su dirección y
   cuánto enviar, y espera. Abre [faucet.solana.com](https://faucet.solana.com), elige **devnet**, pega la
   dirección del dueño y pide unos 0,02 SOL. El comando sigue solo cuando llega el SOL.
3. **Confirma el registro.** Revisa el coste estimado y responde `y` para firmarlo y enviarlo.
4. **Publica.** Pulsa Enter (o `y`) para listar tu oferta en el índice de descubrimiento.

Cuando los dos pasos terminan bien, el instalador muestra:

```text
Done: this seller is registered and published. Buyers can find it within about two minutes.
```

Pulsa Ctrl+C en cualquier paso y vuelve a ejecutar `sh install.sh` más tarde: conserva lo hecho y continúa.
Sin terminal, o con `GYBLOS_GUIDED=0`, el instalador solo muestra estos pasos para que los ejecutes tú. Mientras
el vendedor está en marcha, `gyblos seller status` indica el siguiente paso. Los detalles, incluido qué hacer
si el registro se interrumpe, están en [Registra y publica](/es/sellers/register-publish).

## 3. Comprueba el estado [#confirma-el-estado-del-servicio]

En un vendedor Docker, ejecuta los comandos desde la carpeta de instalación:

```sh
cd ~/gyblos-seller
docker compose exec seller gyblos seller status
```

En un vendedor nativo, ejecuta `gyblos seller status`. Su línea `Result:` es una de estas:

| Resultado       | Significado y siguiente paso                                                          |
| --------------- | ------------------------------------------------------------------------------------- |
| `RUNNING`       | El vendedor está atendiendo. Ya terminaste.                                           |
| `STARTING`      | Espera un momento y vuelve a consultar.                                               |
| `FAILING`       | Lee la fase y el código, y sigue la entrada correspondiente en solución de problemas. |
| `STOPPED`       | Vuelve a iniciarlo ([Opera y actualiza](/es/sellers/operate#detén-e-inicia)).         |
| `NOT_CONFIRMED` | No se pudo confirmar el estado del servicio. Revisa `docker compose ps`.              |

Para confirmar que el índice de descubrimiento lista tu vendedor, añade `--online` (`gyblos seller status --online`).
Indica `listed in the index` cuando el listado ya está activo. Sin `--online`, status muestra una línea `Next:`
mientras falte algún paso de registro o publicación.

## Si la instalación se detiene [#problemas-de-instalación]

Lee la línea `FAIL` o `gyblos install:` y búscala en [solución de problemas](/es/help/troubleshooting).
Corrige la causa y vuelve a ejecutar el instalador. Al repetirlo conserva tu configuración, `seller.env` y tus
llaves.

Si un contenedor de Docker está detenido o reiniciándose, `exec` no puede alcanzarlo. Ejecuta el diagnóstico
independiente:

```sh
cd ~/gyblos-seller
docker compose run --rm seller gyblos doctor
```

<Callout type="error" title="Conserva tus llaves">
  `docker compose down -v` borra los volúmenes de Docker, incluidas las llaves
  de tu vendedor, y no se puede deshacer. Un código de invitación usado no puede
  registrar llaves nuevas. Para detener el vendedor, ejecuta `docker compose
  stop seller`.
</Callout>

## Qué envía tu vendedor

Las versiones publicadas envían recibos firmados sin contenido y observaciones de telemetría al recolector de
métricas de Gyblos, y `gyblos seller status` consulta GitHub para ver si hay una versión nueva. Los recibos y
las observaciones nunca contienen preguntas ni respuestas. Para desactivar las observaciones, consulta
[qué envía tu vendedor](/es/sellers/operate#datos-que-envía-tu-vendedor).
