---
title: Troubleshooting
description: Find your symptom or error code and fix it safely, for the Docker or native seller, the desktop app and the local buyer.
---

Find the symptom or the exact error, then follow its remedy. While you diagnose, keep the seller's keys,
home folder and Docker volumes: deleting them never fixes a seller and can lose its identity for good.

## Check the seller's state [#start-with-the-service-state]

For the Docker seller:

```sh
cd ~/gyblos-seller
docker compose ps
docker compose exec seller gyblos seller status
```

For the native seller:

```sh
gyblos seller status
```

| Result          | What to do                                                                              |
| --------------- | --------------------------------------------------------------------------------------- |
| `RUNNING`       | The seller is serving. This doesn't prove that it is listed or that a buyer reached it  |
| `STARTING`      | Wait a moment and check again                                                           |
| `FAILING`       | Read the phase, code and hint, then find the code on this page                          |
| `STOPPED`       | Docker: `docker compose up -d --force-recreate seller`. Native: run the installer again |
| `NOT_CONFIRMED` | Status couldn't confirm the process: check that the container or service is actually up |

If `exec` says the service is stopped or restarting, run doctor instead:

```sh
cd ~/gyblos-seller
docker compose run --rm seller gyblos doctor
```

Doctor probes the seller's dependencies and prints its public identity, with a code and a hint for each
failure. For the default setup, check Ollama first. Add `--online` only when you want it to contact remote
engines and the discovery index too.

## The installer stops [#installation-errors]

Every installer error starts with `gyblos install:`. Fix the named cause, then run the installer again
from where you saved it: it keeps existing files, keys and identity, and continues where it stopped.

### Docker [#docker]

| Exact output                                                | Remedy                                                                                                                                          |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `Docker is not installed` or `Docker Compose v2 is missing` | Install Docker with the Compose plugin, v2.17 or later                                                                                          |
| `Docker is not running, or this account may not use it`     | Start Docker Desktop or the Docker service. On Linux, the account may also need Docker access; see the [requirements](/en/getting-started/beta) |
| `Docker Compose … is too old`                               | Update Docker or Compose to v2.17 or later                                                                                                      |

When Docker is installed but this account can't use it, a new install sets up the native seller instead
and says so. Run `GYBLOS_MODE=docker sh install.sh` to insist on Docker.

### Ollama [#ollama]

| Exact output                                                         | Remedy                                                                                                        |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `Ollama did not start`                                               | Read `docker compose logs ollama` privately; check memory, disk space and Docker's health                     |
| `The seller serves its model with Ollama, which is not running here` | Install Ollama from [ollama.com/download](https://ollama.com/download), open it, then run the installer again |
| `Ollama could not pull qwen3:0.6b`                                   | Run `ollama pull qwen3:0.6b`, then run the installer again                                                    |

### Native seller [#native-installation-errors]

| Exact output                                                     | Remedy                                                                                            |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `The packaged seller needs glibc`                                | Alpine and other musl systems use the Docker seller: install Docker, then run the installer again |
| `Intel Macs install the seller with Docker`                      | Install Docker Desktop, then run the installer again                                              |
| `The seller is not ready; fix the failures above`                | Fix each doctor failure printed above it, then run the installer again                            |
| `The background service could not be installed`                  | Fix what the service step printed, then run the installer again                                   |
| `config.toml is changed, but the seller service did not restart` | Run the installer again, or `gyblos seller service install`, so the change applies                |

### Any install [#installer-checks]

| Exact output                                                                                | Remedy                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GYBLOS_RELAY_TOKEN has characters…` or `GYBLOS_RELAY_TOKEN must have 32 to 512 characters` | The optional relay token you set is malformed. The Gyblos relays need none: unset `GYBLOS_RELAY_TOKEN` and run the installer again. Never paste the token in a chat      |
| `GYBLOS_RELAY_TOKEN holds the gyb_ invite code`                                             | Unset `GYBLOS_RELAY_TOKEN` and run the installer again. Enter the invite code later with `gyblos seller register` ([Register and publish](/en/sellers/register-publish)) |
| `The image signature did not verify`, or a download that doesn't match its checksum         | Don't run that file or bypass the check. Download the installer again from `https://gyblos.com/install.sh` and report it in the [Gyblos Telegram](https://t.me/gyblos)   |

## The configuration is rejected [#configuration-rejected]

```sh
cd ~/gyblos-seller
docker compose run --rm seller gyblos config validate --config /config/config.toml
```

Fix each issue at the key path it reports, such as `offers[0].free.per_buyer_cap`. If startup still
refuses a file that validates, run doctor. Defaults and ranges are in the
[configuration reference](/en/reference/configuration).

| Code                                                                                                      | Remedy                                                                                                                                                          |
| --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FILE_NOT_FOUND` from validation                                                                          | Pass the path explicitly, as above. The validator ignores `GYBLOS_CONFIG`                                                                                       |
| `TOML_SYNTAX`, `UNKNOWN_KEY`, `WRONG_TYPE`                                                                | Fix the syntax, remove the unknown key or use the required type. Don't repeat `[discovery]` or a model's offer                                                  |
| `INVALID_CAP`                                                                                             | Use positive integers; the per-buyer cap can't exceed the daily total                                                                                           |
| `INVALID_LIMIT`                                                                                           | Keep each capacity value in range, and connections × per-buyer rate within the global rate                                                                      |
| `INLINE_SECRET`                                                                                           | Remove the credential from TOML; name a variable and set it in `seller.env`. Rotate an exposed credential with its issuer                                       |
| `RELAY_ONLY_CONFLICT`                                                                                     | Remove the external address or turn relay-only off, including environment overrides                                                                             |
| `SELLER_SETTING_UNSUPPORTED`                                                                              | Remove `node.data_dir`, `node.rpc_url` or `node.payout_wallet` from the file                                                                                    |
| `SELLER_OFFERS_MISSING`                                                                                   | Add back at least one supported offer                                                                                                                           |
| `SELLER_OFFER_MODEL_UNSUPPORTED`, `SELLER_OFFER_ENGINE_UNSUPPORTED`, `SELLER_OFFER_REASONING_UNSUPPORTED` | Return to the local Qwen3 offer with reasoning `off`, or check the [engine rules](/en/reference/configuration#engine-compatibility-at-startup)                  |
| `SELLER_OFFER_API_KEY_MISSING`, `SELLER_OFFER_API_KEY_UNSAFE`                                             | Set the provider's key in `seller.env`, under a name that doesn't start with `GYBLOS_` and isn't the relay token's                                              |
| `MAINNET_UNSUPPORTED`                                                                                     | Keep `network = "devnet"`; mainnet is not open                                                                                                                  |
| `SELLER_PAYMENT_ROLE_MISSING`                                                                             | The payment keys are missing: run the installer again (it keeps the NodeId and owner), then fund the fee payer ([Get paid](/en/sellers/get-paid))               |
| `FEE_PAYER_UNFUNDED`                                                                                      | Below 0.01 devnet SOL. A zero balance fails the check if token accounts are missing. See [Get paid](/en/sellers/get-paid)                                       |
| `SELLER_PAYMENT_ACCOUNTS_UNAVAILABLE`, `PAYMENT_ACCOUNTS_MISSING`, `PAYMENT_ACCOUNTS_UNCHECKED`           | Send devnet SOL to the `fee payer` address that `gyblos doctor` prints, then retry; startup creates the token accounts. `UNCHECKED` means the RPC didn't answer |
| `PAYMENT_ACCOUNTS_UNUSABLE`                                                                               | A payout or fee token account is frozen or isn't a token account. Don't start a priced offer; ask in the [Gyblos Telegram](https://t.me/gyblos)                 |

## The engine or relay is unavailable [#engine-or-relay-unavailable]

### Engine [#engine]

| Code or symptom                            | Remedy                                                                                                                          |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| `ENGINE_UNAVAILABLE`, `ENGINE_TIMEOUT`     | Check that Ollama runs and that `qwen3:0.6b` is downloaded. Read Ollama's logs privately. Keep the engine URL the installer set |
| Docker seller fails after Ollama restarted | Run `docker compose restart seller`, then check status: both share one network namespace                                        |

### Relay [#relay]

| Code or symptom                                     | Remedy                                                                                                                                                     |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SELLER_RELAY_OFFLINE`                              | No Gyblos relay answered at startup. Check internet access over HTTPS and UDP port 7842                                                                    |
| `INVALID_RELAY_TOKEN`, `INVALID_RELAY_TOKEN_LENGTH` | The Gyblos relays need no token. Delete the `GYBLOS_RELAY_TOKEN` line from `seller.env` in a private editor, keep the other lines, then restart the seller |

## Running but not listed [#running-but-not-listed]

Work through [Register and publish](/en/sellers/register-publish): confirm the registration,
`publish = true`, a restart after the edit, then `gyblos seller status --online`. Check that you query the
same index where you registered and that at least one offer is ready.

### Registration [#registration]

| Code or output                      | Meaning and remedy                                                                                                                |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `DISCOVERY_IDENTITY_NOT_REGISTERED` | Run `gyblos seller register` again in an interactive terminal. The owner needs devnet SOL; read the cost and approval steps first |
| `REGISTER_IDENTITY_UNAVAILABLE`     | The registration didn't complete: read the hint about missing SOL, the simulation or an uncertain result before you retry         |
| `REGISTER_CANCELLED`                | You answered something other than `yes` or `y`: nothing was signed or sent. Run `gyblos seller register` again                    |
| `DISCOVERY_INVITE_INVALID`          | The code is wrong, used or expired. Ask for a new one in the [Gyblos Telegram](https://t.me/gyblos); don't post the old code      |
| `DISCOVERY_NODE_REVOKED`            | Ask in the [Gyblos Telegram](https://t.me/gyblos). Don't create another identity to get around the removal                        |
| `DISCOVERY_RATE_LIMITED`            | Wait a minute before you retry                                                                                                    |
| `DISCOVERY_UNAVAILABLE`             | Try later or ask in the [Gyblos Telegram](https://t.me/gyblos). Check the configured index before you submit an invite            |

A repeated `register` checks its saved state and may resend the transaction you already approved. Keep every
file and lock. Read the [recovery limits](/en/sellers/register-publish) before you run it again, and never
clear state to force another attempt.

### Visibility [#visibility]

If the seller is registered and `publish = true`, but `gyblos seller status --online` still doesn't show it as listed:

| Code or output                                   | Meaning and remedy                                                                                                                                                                                                                                                                                               |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `not found in the index` two minutes after start | During the beta, only sellers whose identity redeemed an invitation are listed. Check that `gyblos seller register` printed `Registered` or `Already registered` for this identity, or run it again. If it did, ask in the [Gyblos Telegram](https://t.me/gyblos) with your public NodeId, never the invite code |
| `not in the first 2000 sellers`                  | The search stopped early; this doesn't prove the seller is missing                                                                                                                                                                                                                                               |
| `index unreachable`                              | The listing state is unknown; fix connectivity first                                                                                                                                                                                                                                                             |
| `CLOCK_SKEWED`                                   | Turn on automatic time synchronization; the index can reject records dated in the future                                                                                                                                                                                                                         |

## Requests are refused or there is no activity [#free-requests-refused-or-no-activity]

When a request arrives, an offer reserves its input plus its maximum output. So a request can be refused
even when some daily or per-buyer allowance remains. Capacity and distinct-buyer limits can also refuse
requests. Review [Change models and limits](/en/sellers/models-offers); don't restart to get around a
limit. A listing alone doesn't bring buyers.

## Missing keys, corrupt state or locks [#missing-keys-corrupt-state-or-locks]

Keep the volume or home folder as it is and ask for help. Don't delete a lock, journal, role file or key to
make a check pass, don't run setup into another home, and never run `docker compose down -v`. See
[Identity and backups](/en/sellers/identity).

## Desktop app and local buyer [#buyer-and-desktop]

| Symptom or exact output                                                                | Remedy                                                                                                                                                            |
| -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| macOS says it can't verify the developer, or Windows shows "Windows protected your PC" | Expected for the unsigned beta app; follow the [first-run steps](/en/buyers/desktop-app#install)                                                                  |
| The wallet shows **Locked**                                                            | Expected until you unlock it; free chat doesn't need it. To use it, see [Protected wallet](/en/buyers/desktop-app#protected-wallet)                               |
| The wallet shows **Not available**                                                     | macOS: allow "Gyblos Safe Storage" in the Keychain dialog. Linux: run GNOME Keyring or KWallet and restart the app. Then choose **Set up or unlock wallet** again |
| `Local buyer is unavailable`                                                           | Choose **Payments → Retry local buyer**. It retries startup only                                                                                                  |
| An answer fails with HTTP 503, or no seller is available                               | No registered seller is online for that model right now. Wait and try again; check that you can reach the internet                                                |
| An error says the seller was too slow (`engine_timeout`)                               | Send the message again; another seller usually answers. With a coding agent, you can also shorten or compact the conversation                                     |
| `An unfinished payment needs review. New messages are blocked.`                        | Open **Payments** and review the payment. Don't delete app data to clear it; ask for help if it stays unresolved                                                  |

A paid request can be refused even when the wallet has USDC. An expired
channel or a channel with verified final settlement cannot fund another turn.
Check its status in **Payments** before authorizing a new deposit. An uncertain
channel stays blocked while the buyer checks the evidence. A delegated key
under review pauses Desktop and connected coding tools. A status check never
sends the question or creates a deposit.

## Ask for help safely [#ask-for-help-safely]

Write in the [Gyblos Telegram](https://t.me/gyblos) with the error code and these outputs. The group is
public: everyone in it can read what you post.

```sh
cd ~/gyblos-seller
docker compose exec seller gyblos seller status
docker compose images seller
```

For a native seller, send the output of `gyblos seller status` and `gyblos --version`. If status doesn't
run, send the doctor code instead. Review the output before you send it. Never send `seller.env`, invite
codes, raw logs, environment dumps, `docker inspect` output, receipts, key files or volume contents.

Desktop checks the selected seller against the running buyer before sending. If the selected response limit exceeds the verified channel funds, review the replacement deposit. Refresh the wallet separately when its balance is unavailable.
